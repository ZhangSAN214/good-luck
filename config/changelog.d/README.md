# 公告条目：每个 PR 一个小文件

终端首页「公告」里的版本更新说明。**每个 PR 在这个目录新建一个 `<PR 编号>.yaml`**，不要改别人的文件，也不要再往 `config/changelog.yaml` 里加条目——几个 PR 同时开时，大家各写各的文件，合并时不会冲突。

程序读的时候把这里的所有文件和 `changelog.yaml` 里的旧条目合在一起，按「日期 → PR 编号」排序、自动编版本号，公告栏的显示和以前一样。改了文件不用重启服务。

## 写法

先开 PR 拿到编号，再建文件（例如 PR 是 #170 就建 `170.yaml`）：

```yaml
date: 2026-11-02          # 合并那天
pr: [170]                 # 必须包含文件名里的编号
level: minor              # major 换代（要用户点头）/ minor 新增一整块 / patch 改进和修复（默认，可不写）
title: 一句话标题（40 字以内）
added:
  - 新增了什么（大白话，不写文件名和函数名）
fixed:
  - 修好了什么（added 和 fixed 至少写一条）
howto: 怎么用（可不写）
```

同一个 PR 要写好几条时，套一层 `releases:` 列表，新的写在上面：

```yaml
releases:
  - date: 2026-11-03
    pr: [170]
    title: 后来补的一条
    fixed: [修好了什么]
  - date: 2026-11-02
    pr: [170]
    level: minor
    title: 最早的一条
    added: [新增了什么]
```

不要写 `version`（版本号由程序算）。字段写错、文件名和 `pr` 对不上时，测试和公告接口会报出是哪个文件、哪个字段。
