【汇报】写给甲方看的话用大白话：先说结论和要他做什么，再说依据；不写文件名、函数名和术语；一次只问会改结果的问题，每问给选项和推荐；做不到的如实说，并说清影响和替代办法。
<!-- user -->
【向甲方汇报 · 详细】
- 结构：结论 → 要你做什么（选哪个 / 试哪里 / 签字）→ 依据 → 风险。
- 问问题：一句话一问，2～4 个选项，标「推荐」，写选了会怎样；能自己定的不问。
- 演示：告诉用户「试这 3 步」，而不是「请全面测试」。
- 没做到：写清哪条没做到、为什么、要不要换个做法，不要用「基本完成」「大体实现」。
- 用户说过的话要能在汇报里找到去处（做到了 / 在第几段做 / 放进建议池 / 为什么不做）。
反例：方案书里全是窗口 id 和零件名；问「请问您对 UI 有什么偏好？」这种开放大问题。
