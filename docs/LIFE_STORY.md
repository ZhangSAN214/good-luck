# 成员生活引擎（P7：L0 底座 + L10 擅长觉醒 + L1 日常细节 + L2 节日纪念日 + L4 健康与低谷 + L5 旅行）

方案：「成员生活系统：全面补全方案」（2026-10-30）。用户 2026-10-31 批了 5 点：能轻度生病（只限过敏、拉伤这类，几天就好）；旅行时工作照常；成员离开 / 新成员入住当生活事件；先做 L0 → L10 → L1 → L2 → L4；生活日上限维持 $0.15。

代码在 `src/roundtable/core/member/story/`，规则在 `config/roundtable.yaml` 的 `chat.life.story`。**全程序、不调用模型**：内容变丰富靠程序挑事，只有原来就会写成聊天的那几件（群聊、私聊、朋友圈、日记）多了可说的东西，所以生活花费不变。

## 怎么转

1. **程序挑事**（每位成员每个主时区的日子挑一次，随机数由成员 + 日期派生，可复现）：
   - 先接着进行中的长线剧情（感冒第 0 天嗓子疼 → 第 1 天躺着 → 第 2～4 天好了）；
   - 再按擅长的阶段（L10，下一节）；
   - 最后从事件库里挑：看星期、月份（季节）、档案里的爱好（`likes` 命中时概率 × `boost`；`need_likes` 时没提到就不会发生，比如不运动的人不会运动拉伤）、觉醒了的擅长（相关的事 × `story_boost`）、冷却（同一件事 `cooldown_days`，同一分组 `group_cooldown_days`：每季度最多病一次、每月最多一件小意外）。
   - 每人每天最多 `max_per_day`（2）件：大部分日子是平淡的（60 天 × 6 人的测试里，多数「人·天」什么都没发生）。
2. **事有因果和后续**：一件事的几步（`steps`）在开始那天就排好日子和钟点，存在她的生活状态里（`app_settings` 的 `member_life:<成员>`），到点发生。
3. **只发事件**：到点的事写成 `life_events` 的一行（kind = `story`），场景是「地点：自己的宿舍（脚踝还肿着，在房间歇着）」加一行 `生活事件：id/步/领域`。之后各插件自己接，本系统不越权：
   - 心情精力 **P3**：成员引擎转到总线时带上这一步的标签（`story.sick` 不舒服、`story.good` 好事、`story.tired` 犯困……），按反射表（`chat.engine.state.reflexes`）改；
   - 记忆 **P2**：夜间整理时当作没写成聊天的生活小事，记进日记和记忆件；
   - 档案 **P6**：擅长由成长插件写（见下）；关系 P4 照旧只看聚会和私聊。
   - 私聊里「你刚才在……」（`life_clock`）也会读到最近这件事。
4. **模型只把值得说的说出来**：生活群 / 成员私聊的场景里多一行「最近各自的事（背景，自然地带到就行）」：在场的人最近 2 天发生过的事，最多 2 件、80 字；深耕了的擅长带一句「楼里东西坏了都找小克」这样的自然话。不加引号、不给可照抄的原句（10-31 群聊线程提醒：生活群第 19 条就是原句连引号漏出来的）。

## 空闲去哪（按爱好，不按编号轮换）

作息表里的空闲时段（锻炼、聊天、看星星、打游戏、看书）以前按住户编号和日期轮换，8 个人轮着去健身房。现在按各自档案里的爱好加权挑（`way.options`：去处 → 词；档案提到得多的权重最多 + `like_weight`，觉醒了的擅长相关的去处再 + `talent_weight`），之后照旧交给大脑分区按驱力、习惯、目标再挑。22 点以后照旧回宿舍。生病歇着的那天空闲时段在宿舍「歇着」，上班时间照常（旅行时工作照常同理）。

## 住户变化

配置里的成员（不论这台电脑有没有 key）和上次记下的名单比：新来的记一件「刚搬进公寓，还在收拾行李」，原来的住户记一件「X 搬进来了，大家去打了个招呼」；下架的，认识 TA 的住户记一件「X 搬走了，走之前和大家道了别」。温和，不煽情。第一次只记名单。

## 和生活阶段的分工

`chat.engine.phase`（10-31 拟人插件调研第 7 项）已经管「忙季、小感冒、迷上一样东西、收拾屋子、熬夜赶东西、放松」这类持续几天的阶段，所以事件库**不再排感冒**，只管过敏、运动拉伤、牙疼；她正在「小感冒」阶段时也不会再排 sick 组的事（`phase_groups`）。L4 把两边合起来：小感冒那几天空闲时段也在宿舍歇着，也会有朋友来照顾（见下节）。生活阶段只读，`member_phase` 的格式不动（成长总账照旧读）。

## L10 觉醒擅长领域

擅长只长在「人」身上：**证据只有人物卡种子 + 生活练习，不看办公室表现，也不影响办公室派活**（10-30 用户：办公室的模型是电脑，群聊里的成员是人）。领域清单在 `talent.domains`（推理、编程、写作、语言翻译、长文阅读、资料检索、整理归纳、画画审美、音乐、天文科学、历史文学、做饭、手工修理、记账理财、倾听照顾人、活跃气氛、运动、游戏，可增删），不按厂商写死，8 位同一套规则和阈值。

- **证据分** = 档案里提到这个领域的词的次数（最多 `seed_cap` 次）× `seed_weight` + 最近 `window_days`（30）天的练习次数。练习 = 生活事件里做过的相关的事：去处对上 `acts`（天台看星星、宿舍看书、健身房锻炼……）、大脑琢磨的事名字里有这个领域的词、事件库里带这个 `domain` 的事、有人来请教。
- **萌芽**：证据分到 `sprout` 且练过至少一回。她自己还没说，不发事件。
- **觉醒**：证据分到 `awake` 且练习 ≥ `awake_practice`（只有种子不够），发一件「突然意识到自己好像挺会天文科学的：最近 30 天里看星星 12 回，本来也喜欢」——说得出依据，不凭空吹；交给 P6 写进档案 `likes.擅长`（以成长的身份，一项一个版本，记进成长时间线，能一条条撤回；用户锁住这一项时不动）。最多同时 `max_talents`（3）个。
- **深耕**：觉醒后 `deep_days` 天还在练（≥ `deep_practice`）：空闲时更常去做；每天有 `ask_chance` 的机会有人来请教（两人都记一笔）；有 `stuck_chance` 的机会卡住几天（`stuck_days`）再想通（心情先沉一下再好起来）。
- **生疏**：觉醒后窗口里练习不超过 `rusty_practice` 回：发一件「好久没碰了，手有点生」，交给 P6 从档案去掉，回到萌芽。
- 界面和数据里没有等级、排行榜、分数：只有一句自然话。

## 守卫（`tests/core/member/story/`）

- 单向隔离：编排引擎、步骤、路由、分配、提示词、办公室、预算的代码不 import 生活引擎、不读生活状态和 `likes.擅长`；有了生活事件和擅长后跑一场讨论，发给模型的每条消息都不含生活事件、擅长和练习内容。
- 不越权：生活引擎只调 `setting` / `set_setting` / `life_events_between`，不写档案（`.change(` 不出现），不读会话、调用、办公室记录和 `work.done`。
- 可复现、大部分日子平淡、长线剧情的几步按天展开、分组冷却、`need_likes`、按爱好挑去处、住户迎新 / 告别、标签进 P3、事件进 P2 记忆材料、场景行不带引号和原句标记、半小时推进和一天推进结果一样。
- 旅行（`test_travel.py`）：一趟按计划 → 收拾 → 出发 → 途中 → 回来 → 早睡的顺序发生；在路上只发生旅行的事；外地的去处、上班照常；同时在外面的人数和冷却；目的地按爱好挑；公寓名册显示不在家；生活排日程时她在外地、不和别人「碰到一起」；关掉旅行时不出门的人其余的事一模一样。
- 打卡和 B 站（`tests/core/member/checkin/`）：判定卡过了才写日记、默认不出图；排除项、偷懒的动作、低分不过；结构化拍法带固定约束；日记只带前 3 天；额度和钱在调用前检查；花费都在 `travel` 步骤；B 站只看她今天逛过的视频页、额度、总开关、私信 / 动态每人每天各 1 条、没有 yt-dlp 或没钱时什么都不做；B 站模块里没有发消息的接口；工作模式代码不碰打卡和 B 站。
- 擅长：只有种子不觉醒；种子 + 练习觉醒并带依据；P6 写档案、能撤回、不重复写；同样的证据 8 位结果相同；深耕有人来请教、自然话里没有数字；卡住后一定跟着想通；长期不练生疏并从档案去掉；最多几个；觉醒后空闲时更常去做；办公室的事不算练习。

## L1 日常细节

- **作息、饮食、家务、季节**（事件库，`config/roundtable.yaml` 里「L1 日常细节」那一段）：工作日赖床、周末午睡、失眠（第二天犯困，P3 接 `story.tired`）、做梦、发呆；外卖、夜宵、自己做饭、拉人尝新店；口味（`need_likes`：档案里提到辣 / 甜的人才会有「吃了顿很辣的」）；周末洗衣服、打扫、挪家具；季节只在对应月份（11～2 月涮火锅、第一次冷得翻出厚外套，9～11 月踩落叶，3～5 月看花，6～8 月吃冰棍）。概率都很低，大部分日子照旧平淡。
- **爱好进度**（`progress.kinds`：书、剧、游戏，可增删）：每种爱好同时只在做一样东西，优先从她档案「最爱」里挑含这种爱好的词的那一项（各人不同），没有再从配置里挑。前一天生活里做了相关的事（宿舍看书、休息室打游戏）才往前推几格；追剧没有对应去处，每天按 `daily` 的机会推。推进那天偶尔顺嘴记一句「推理小说看到第 8 章了」，推满记一件「把推理小说看完了」（好事），隔 `gap_days` 天再开始下一样。中途和看完算对应擅长领域的练习，「开始看」不算。进度存在她自己的生活状态里，每天的上限（`max_per_day`）照旧：记不下的那天进度照推、只是不记一笔。
- 原来事件库里的「把一本书看完了」「那一关打过去了」被爱好进度取代，删掉了。
- 天气还没接：后端没有天气数据（只有前端天空图），先用月份代替。

## L2 节日纪念日

读日历（`core/almanac`，和日历页、大脑念头同一份），不另算日子；规则在 `festival`。一天只排一次（`member_life_festival` 记排到哪天），排进领头那位的日程，到点发生。

- **节日**（`festival.festivals`，可增删）：日历条目的名字含 `match` 里的字就算。提前 `prep_days` 天有一位去准备（买对联饺子皮、月饼、南瓜、圣诞树），当天在场的大家一起过（除夕包饺子看春晚、中秋上天台赏月、万圣节刻南瓜灯、篝火夜看烟花、圣诞交换礼物……）。
- **按来历过节**：`origin` 是来历词，档案里提到这些词的成员把它当家乡的节日：由她领头张罗，当天晚上还会有点想家（P3 接 `story.homesick`，心情轻轻沉一下）。没写来历的谁都一样过。
- **成员生日**：前一天有人偷偷准备礼物，当天大家给她过。礼物从寿星档案的「最爱」里挑（「一个和星星有关的小礼物」），没有就从 `gifts` 挑；送礼的人和礼物由寿星和年份决定，前一天和当天对得上。
- **入住周年**：成员第一次在圆桌说话那天算入住，满 N 年那天翻翻刚来时的照片。
- 这些事不受每天上限，但会占掉领头那位当天的名额。日历关了（`calendar.enabled`）或 `festival.enabled` 关了就不排。

## L4 健康与低谷

规则在 `lows`，全程序，只看她自己的生活（生活事件、生活阶段），不看办公室。

- **病了有人照顾**：她不舒服的那几天（生活阶段的小感冒，或事件库里带 `story.sick` 的那一步），常一起玩的朋友带碗粥、顺路买药、问好点没（`care_texts`），一场病一次。朋友 = 最近两周生活里和她一起聚得最多的人（读生活事件，不读关系插件的表）。
- **低谷有前因后果**：最近 `window_days`（7）天里接连有 `need_bad`（2）件不顺（糟心事、生病、卡住、有人搬走、想家），按 `low_chance` 可能低落几天：「最近钥匙丢了、又牙疼得睡不着，这几天有点提不起劲」→ 第 1～2 天朋友拉她出去走走 / 陪她打两局游戏（`comfort_texts`）→ 第 3～5 天缓过来。冷却 `low_cooldown_days`（30）天。
- **累久了想歇**：最近熬夜、犯困，加上生活阶段压精力的那几天（忙季、熬夜赶东西），攒够 `need_tired` 就在最近的周末歇一天，那天空闲时段在宿舍「歇着」。
- 都交给 P3 按标签改心情精力（`story.cared` / `low` / `comforted` / `better` / `rest`）。不煽情、不拿生病要人陪；和用户无关（不会因为用户没来而低落）。

## L5 旅行

规则在 `travel`，代码 `story/travel.py`，**全程序、不调用模型**（和别的生活事件一样：程序挑事，模型只在写群聊、朋友圈、日记时顺嘴带到）。

- **偶尔出门，短途为主**：每人每天按 `chance`（0.012，8 位合起来大约一两周有一位出门）想出门，档案里提到 `like_words`（旅行、风景、露营……）时 × `boost`；回来后至少隔 `cooldown_days`（30）天；同一时间最多 `max_away`（2）位在外面。目的地在 `dests`，按档案里的爱好和月份挑（喜欢海的更常去海边小镇，花海只在春天，雪山只在冬天）；目的地都是泛称（海边小镇、古镇、隔壁城市……），不冒充现实里的具体景点（§5.1 第 1 条）。旅行有自己的随机数，开不开旅行，不出门的人其余的事一模一样。
- **前后因果**：计划那天就把整趟排好，每一步是一件 `travel_<步>` 的生活事件：在查票、打算周几出发（今天）→ 前一天晚上收拾行李 → 一大早出发 → 途中每天一件事（最多 3 件）→ 回来给最近常一起玩的朋友带了东西（两人都记一笔）→ 回来当晚腿酸早睡（当天来回的不记这一步）。P3 接 `story.travel`（出门心情好）、`story.trip`、`story.back`（回来有点累）。
- **不在家、工作照常**（10-31 用户定）：出发到回来前的那几天，吃饭、睡觉、空闲时段都在「外地」：生活事件的地点是 `away:<成员>`，场景写「地点：外地（去海边小镇旅行了，不在家）」，不会和楼里的人「碰到一起」；公寓楼名册里显示「去海边小镇旅行了，不在家」，楼里看不到她。**上班时段照作息表**，办公室的派活、绩效、工作提示词一概不动（守卫测试照旧）。在路上的那几天（出发到回来当天）不再排别的生活小事；节日、生日按在家的人过。
- **喂给哪里**：群聊 / 私聊场景里「最近各自的事」照旧会带到（「阿一昨天在海边小镇捡了几个贝壳」）；朋友圈从当天的生活事件里挑（旅行在外面，按 11-02 的规矩不配图）；公寓显示不在家；途中那件事交给旅行打卡（下一节）。

## 旅行打卡（借 dsh-bili-lvxingfeiyu 的思路）

代码 `core/member/checkin/card.py`。只借思路、不搬代码（那个项目是 MIT 许可的 JavaScript 插件，这里是按同样的想法重写的）。**会调用模型**，所以不在 `story` 包里（那边只挑事、不花钱）。

1. **判定卡**（提示词 `checkin_card`）：旅行途中的一件事、或看过的 B 站视频里的一段 → 她判断「我会不会想站进去」，只输出一张 JSON：能不能、为什么、命中哪条排除项、那一刻在发生什么、她在那儿做什么、心情、站位 / 远近 / 朝向、0～20 分。排除项：文字页、真人正脸特写、多人群像、画面里已有动漫角色、大面积水印、空无一事。程序再把关：没过、动作偷懒（「站在那里提着裙摆」「摆个姿势」，除非画面里有风有水有台阶）、分数不到 12 → **不打卡，只记一笔为什么**，不硬写、不硬画。
2. **旅行日记**（提示词 `travel_journal`）：判定卡过了才写。第一人称、第一行是标题、300～600 字、要有碎碎念；带她自己**前 3 天**打过的卡（日期、地方、日记题目、那一刻、她做了什么），前后连得上、不重复。
3. **配图（默认关）**：站位、远近、朝向、动作、神情和固定的一致性约束（正好两只手五根手指、不重画背景、不加别人、不出字和水印）由**代码拼成结构化拍法**（模型只填判定卡的字段，改不动这些约束），交给朋友圈配图同一套绘图和每月上限。网页上「打卡配图」开关打开才画；**要真画图前先问你**。
- **额度写死在代码里**：全体每天最多判 3 次、每人每天 1 次。花费记在 `travel` 步骤，算生活每日上限（$0.15 不变），每次调用前检查；判定一次约 $0.003，日记约 $0.006。

## B 站

代码 `core/member/checkin/bili.py`，界面在顶栏「上网」面板下半部分「旅行与 B 站」。

- **看过**：她自己上网逛 B 站时打开过的视频页（浏览记录里的 `/video/BV…`），或你在面板上贴链接让她看 → 用电脑上的 `yt-dlp` 下载**一条**最低清晰度的原片（不超过 10 分钟、80 MB，不批量抓）→ 均匀取 4 帧存进聊天媒体目录（面板上能看到）→ 交给感官（声音转写 + 宫格图）写成一段「看到了什么」→ 原片删掉。之后记一件生活小事（朋友圈、日记、记忆接着用），再交给旅行打卡判一次。电脑上没有 `yt-dlp` 时什么都不做（`pip install yt-dlp`）。
- **私信和动态，全部自动（用户 11-02 选）**：看完按每天额度自动写（提示词 `bili_share`，可以都不写）：给你的私信一两句、她自己的动态一两句。**只存在这台电脑的列表里，你事后在面板上看；不会用任何账号发到 B 站或别的网站**（真发要你另外确认，见下）。
- **额度写死在代码里**：全体每天自动看 2 个视频、每人 1 个；私信全体 3 条、动态全体 3 条，每人每天各 1 条。
- **一键总开关**：面板上「B 站全部自动」。关掉后不自动看、不自动写私信 / 动态；你手动让她看的照样能看（但不写私信 / 动态）。
- 看视频的感官调用也记在 `travel` 步骤，算生活每日上限。

### 没做：真的发到 B 站

把私信和动态用真实账号发到 B 站，需要登录她们的小号（存 cookie）、调发消息 / 发动态的接口，会以真人身份对外发言。任务要求「会用真实账号向外部网站真的发私信或动态，先停下等你确认」，所以这一版只做到本机列表；模块里没有任何登录和发消息的接口地址（有测试）。你确认后再做：要哪个账号、发给谁、每天几条、发前要不要你点一下。
