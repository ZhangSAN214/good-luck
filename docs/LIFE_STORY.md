# 成员生活引擎（P7：L0 底座 + L10 擅长觉醒 + L1 日常细节）

方案：「成员生活系统：全面补全方案」（2026-10-30）。用户 2026-10-31 批了 5 点：能轻度生病（只限过敏、拉伤这类，几天就好）；旅行时工作照常；成员离开 / 新成员入住当生活事件；先做 L0 → L10 → L1 → L2 → L4；生活日上限维持 $0.15。

代码在 `src/roundtable/core/member/story/`，规则在 `config/roundtable.yaml` 的 `chat.life.story`。**全程序、不调用模型**：内容变丰富靠程序挑事，只有原来就会写成聊天的那几件（群聊、私聊、朋友圈、日记）多了可说的东西，所以生活花费不变。

## 怎么转

1. **程序挑事**（每位成员每个主时区的日子挑一次，随机数由成员 + 日期派生，可复现）：
   - 先接着进行中的长线剧情（感冒第 0 天嗓子疼 → 第 1 天躺着 → 第 2～4 天好了）；
   - 再按擅长的阶段（L10，下一节）；
   - 最后从事件库里挑：看星期、月份（季节）、档案里的爱好（`likes` 命中时概率 × `boost`；`need_likes` 时没提到就不会发生，比如不运动的人不会运动拉伤）、觉醒了的擅长（相关的事 × `story_boost`）、冷却（同一件事 `cooldown_days`，同一分组 `group_cooldown_days`：每季度最多病一次、每月最多一件小意外）。
   - 每人每天最多 `max_per_day`（2）件：大部分日子是平淡的（60 天 × 6 人的测试里，多数「人·天」什么都没发生）。
2. **事有因果和后续**：一件事的几步（`steps`）在开始那天就排好日子和钟点，存在她的生活状态里（`app_settings` 的 `member_life:<成员>`），到点发生。
3. **只发事件**：到点的事写成 `life_events` 的一行（kind = `story`），场景是「地点：自己的宿舍（脚踝还肿着，在房间歇着）」加一行 `生活事件：id/步/领域`。之后各插件自己接，本系统不越权：
   - 心情精力 **P3**：成员引擎转到总线时带上这一步的标签（`story.sick` 不舒服、`story.good` 好事、`story.tired` 犯困……），按反射表（`chat.engine.state.reflexes`）改；
   - 记忆 **P2**：夜间整理时当作没写成聊天的生活小事，记进日记和记忆件；
   - 档案 **P6**：擅长由成长插件写（见下）；关系 P4 照旧只看聚会和私聊。
   - 私聊里「你刚才在……」（`life_clock`）也会读到最近这件事。
4. **模型只把值得说的说出来**：生活群 / 成员私聊的场景里多一行「最近各自的事（背景，自然地带到就行）」：在场的人最近 2 天发生过的事，最多 2 件、80 字；深耕了的擅长带一句「楼里东西坏了都找小克」这样的自然话。不加引号、不给可照抄的原句（10-31 群聊线程提醒：生活群第 19 条就是原句连引号漏出来的）。

## 空闲去哪（按爱好，不按编号轮换）

作息表里的空闲时段（锻炼、聊天、看星星、打游戏、看书）以前按住户编号和日期轮换，8 个人轮着去健身房。现在按各自档案里的爱好加权挑（`way.options`：去处 → 词；档案提到得多的权重最多 + `like_weight`，觉醒了的擅长相关的去处再 + `talent_weight`），之后照旧交给大脑分区按驱力、习惯、目标再挑。22 点以后照旧回宿舍。生病歇着的那天空闲时段在宿舍「歇着」，上班时间照常（旅行时工作照常同理）。

## 住户变化

配置里的成员（不论这台电脑有没有 key）和上次记下的名单比：新来的记一件「刚搬进公寓，还在收拾行李」，原来的住户记一件「X 搬进来了，大家去打了个招呼」；下架的，认识 TA 的住户记一件「X 搬走了，走之前和大家道了别」。温和，不煽情。第一次只记名单。

## 和生活阶段的分工

`chat.engine.phase`（10-31 拟人插件调研第 7 项）已经管「忙季、小感冒、迷上一样东西、收拾屋子、熬夜赶东西、放松」这类持续几天的阶段，所以事件库**不再排感冒**，只管过敏、运动拉伤、牙疼；她正在「小感冒」阶段时也不会再排 sick 组的事（`phase_groups`）。L4（健康与低谷）时再把两边合起来。

## L10 觉醒擅长领域

擅长只长在「人」身上：**证据只有人物卡种子 + 生活练习，不看办公室表现，也不影响办公室派活**（10-30 用户：办公室的模型是电脑，群聊里的成员是人）。领域清单在 `talent.domains`（推理、编程、写作、语言翻译、长文阅读、资料检索、整理归纳、画画审美、音乐、天文科学、历史文学、做饭、手工修理、记账理财、倾听照顾人、活跃气氛、运动、游戏，可增删），不按厂商写死，8 位同一套规则和阈值。

- **证据分** = 档案里提到这个领域的词的次数（最多 `seed_cap` 次）× `seed_weight` + 最近 `window_days`（30）天的练习次数。练习 = 生活事件里做过的相关的事：去处对上 `acts`（天台看星星、宿舍看书、健身房锻炼……）、大脑琢磨的事名字里有这个领域的词、事件库里带这个 `domain` 的事、有人来请教。
- **萌芽**：证据分到 `sprout` 且练过至少一回。她自己还没说，不发事件。
- **觉醒**：证据分到 `awake` 且练习 ≥ `awake_practice`（只有种子不够），发一件「突然意识到自己好像挺会天文科学的：最近 30 天里看星星 12 回，本来也喜欢」——说得出依据，不凭空吹；交给 P6 写进档案 `likes.擅长`（以成长的身份，一项一个版本，记进成长时间线，能一条条撤回；用户锁住这一项时不动）。最多同时 `max_talents`（3）个。
- **深耕**：觉醒后 `deep_days` 天还在练（≥ `deep_practice`）：空闲时更常去做；每天有 `ask_chance` 的机会有人来请教（两人都记一笔）；有 `stuck_chance` 的机会卡住几天（`stuck_days`）再想通（心情先沉一下再好起来）。
- **生疏**：觉醒后窗口里练习不超过 `rusty_practice` 回：发一件「好久没碰了，手有点生」，交给 P6 从档案去掉，回到萌芽。
- 界面和数据里没有等级、排行榜、分数：只有一句自然话。

## 守卫（`tests/core/member/story/`）

- 单向隔离：编排引擎、步骤、路由、分配、提示词、办公室、预算的代码不 import 生活引擎、不读生活状态和 `likes.擅长`；有了生活事件和擅长后跑一场讨论，发给模型的每条消息都不含生活事件、擅长和练习内容。
- 不越权：生活引擎只调 `setting` / `set_setting` / `life_events_between`，不写档案（`.change(` 不出现），不读会话、调用、办公室记录和 `work.done`。
- 可复现、大部分日子平淡、长线剧情的几步按天展开、分组冷却、`need_likes`、按爱好挑去处、住户迎新 / 告别、标签进 P3、事件进 P2 记忆材料、场景行不带引号和原句标记、半小时推进和一天推进结果一样。
- 擅长：只有种子不觉醒；种子 + 练习觉醒并带依据；P6 写档案、能撤回、不重复写；同样的证据 8 位结果相同；深耕有人来请教、自然话里没有数字；卡住后一定跟着想通；长期不练生疏并从档案去掉；最多几个；觉醒后空闲时更常去做；办公室的事不算练习。

## L1 日常细节

- **作息、饮食、家务、季节**（事件库，`config/roundtable.yaml` 里「L1 日常细节」那一段）：工作日赖床、周末午睡、失眠（第二天犯困，P3 接 `story.tired`）、做梦、发呆；外卖、夜宵、自己做饭、拉人尝新店；口味（`need_likes`：档案里提到辣 / 甜的人才会有「吃了顿很辣的」）；周末洗衣服、打扫、挪家具；季节只在对应月份（11～2 月涮火锅、第一次冷得翻出厚外套，9～11 月踩落叶，3～5 月看花，6～8 月吃冰棍）。概率都很低，大部分日子照旧平淡。
- **爱好进度**（`progress.kinds`：书、剧、游戏，可增删）：每种爱好同时只在做一样东西，优先从她档案「最爱」里挑含这种爱好的词的那一项（各人不同），没有再从配置里挑。前一天生活里做了相关的事（宿舍看书、休息室打游戏）才往前推几格；追剧没有对应去处，每天按 `daily` 的机会推。推进那天偶尔顺嘴记一句「推理小说看到第 8 章了」，推满记一件「把推理小说看完了」（好事），隔 `gap_days` 天再开始下一样。中途和看完算对应擅长领域的练习，「开始看」不算。进度存在她自己的生活状态里，每天的上限（`max_per_day`）照旧：记不下的那天进度照推、只是不记一笔。
- 原来事件库里的「把一本书看完了」「那一关打过去了」被爱好进度取代，删掉了。
- 天气还没接：后端没有天气数据（只有前端天空图），先用月份代替。
