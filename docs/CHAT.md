# 聊天与成员生活（G1～G7）

> 2026-10-23 用户确认：群聊升级为私聊、工作群、生活群、朋友圈；成员在用户不在时也有自己的生活与工作，可以上网看公开的新闻和帖子。
> **聊天这一块每月花费硬上限 $5**（`chat.budget.monthly_usd`，也计入总预算），按约 $3～4 安排。设计原稿：项目资料 `计划/群聊与成员生活_设计.md`。
> 产品原则（CLAUDE.md §5.1）不变：成员坦诚是 AI；不主动私聊用户、不推送、不挽留、不打卡；不一味附和；记忆与聊天记录只存本地。
> 中立性：工作模式与办公室的提示词不受人设、记忆、生活内容影响（有测试守卫）。

## G1 多会话（2026-10-23）

- 表：`chat_rooms`（迁移 15：`id`、`kind`（`group` 群 / `work` 工作群 / `dm` 私聊）、`title`、`members`（JSON；群的空数组 = 全体）、`with_user`（成员之间的私聊为 0，用户只能旁观，G4 用）、`last_read`）；`chat_messages` 加 `meta`（JSON：来源链接、「你不在时」标记等）。
- 默认会话：生活群 `main`（`chat.life_title`，默认「大家庭」，即原来的群）、工作群 `work`（`chat.work_title`）；私聊 `dm:<成员 id>` 第一次打开时建立，会话列表里每位成员都有入口。
- `core/chat.py`：`ChatHub`（全部会话、按需建私聊、会话列表带未读数和最后一条）；`GroupChat` 按会话类型选提示词（群 `chat/v1`、工作群 `chat_work/v1`、私聊 `chat_dm/v1`）。私聊里只有对方回应（写「大家」或 @ 别人也一样）。
- 每个会话一个隐藏会话（`workflow = 'chat'`）记调用；**聊天月预算** `chat_budget()` = 本月（UTC）全部 `chat` 隐藏会话的花费，加一条回应的预估超过 `chat.budget.monthly_usd` 时不再调用，在会话里说明。
- 未读：别人（成员）的消息在 `last_read` 之后算未读；拉取会话消息（非搜索）时标为已读；系统消息不算。
- 接口：`GET /api/chat/rooms`（会话列表、全体成员、正在输入、本月聊天花费与上限）；`GET/POST/DELETE /api/chat` 加 `room`（默认 `main`，不存在 404）。
- 网页：左边会话列表（群聊 / 私聊，未读红点，最后一条消息），中间聊天，右边群成员（私聊时隐藏）；记住上次打开的会话；左下角显示本月聊天花费。公寓楼的住户卡片新增「私聊」。

## G2 工作群接入办公室（2026-10-23）

- `core/chat_work.py`：服务层收到办公室会话的编排事件（`office_assigned`、`checkpoint`、`completed`、`failed`）时，往工作群写一条系统消息（派给谁 / 召集开会 / 项目组 / 等你拍板 / 交付与花费 / 没办成），meta 带 `session_id`。**不调用模型、不花钱**；写失败只记日志，不影响办公室里的事。
- 匿名开启且未揭晓的办公室会话：只写「经理」「一位员工」「N 位员工」，不写名字（有测试）。
- 群里交办：工作群输入框旁的「交给办公室」（`POST /api/chat/handoff`）按办公室模式、默认档位开一件事；工作群里记下这条交办（标「已交给办公室」）。超过单件上限时照常在办公室弹卡片，工作群提示「在等你拍板」。
- 未读：带 meta 的系统消息（办公室通知）算未读，普通系统提示（掉线、预算）不算。
- 网页：工作群的系统消息和交办消息旁有「查看」，点了回到办公室里的这件事。
