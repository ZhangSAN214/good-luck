# 聊天与成员生活（G1～G7）

> 2026-10-23 用户确认：群聊升级为私聊、工作群、生活群、朋友圈；成员在用户不在时也有自己的生活与工作，可以上网看公开的新闻和帖子。
> **聊天这一块每月花费硬上限 $5**（`chat.budget.monthly_usd`，也计入总预算），按约 $3～4 安排。设计原稿：项目资料 `计划/群聊与成员生活_设计.md`。
> 产品原则（CLAUDE.md §5.1）不变：成员坦诚是 AI；不主动私聊用户、不推送、不挽留、不打卡；不一味附和；记忆与聊天记录只存本地。
> 中立性：工作模式与办公室的提示词不受人设、记忆、生活内容影响（有测试守卫）。

## G1 多会话（2026-10-23）

- 表：`chat_rooms`（迁移 15：`id`、`kind`（`group` 群 / `work` 工作群 / `dm` 私聊）、`title`、`members`（JSON；群的空数组 = 全体）、`with_user`（成员之间的私聊为 0，用户只能旁观，G4 用）、`last_read`）；`chat_messages` 加 `meta`（JSON：来源链接、「你不在时」标记等）。
- 默认会话：生活群 `main`（`chat.life_title`，默认「大家庭」，即原来的群）、工作群 `work`（`chat.work_title`）；私聊 `dm:<成员 id>` 第一次打开时建立，会话列表里每位成员都有入口。
- `core/chat.py`：`ChatHub`（全部会话、按需建私聊、会话列表带未读数和最后一条）；`GroupChat` 按会话类型选提示词（群 `chat/v1`、工作群 `chat_work/v1`、私聊 `chat_dm/v1`）。私聊里只有对方回应（写「大家」或 @ 别人也一样）。
- 每个会话一个隐藏会话（`workflow = 'chat'`）记调用；**聊天月预算** `chat_budget()` = 本月（UTC）全部 `chat` 隐藏会话的花费，加一条回应的预估超过 `chat.budget.monthly_usd` 时不再调用，在会话里说明。
- 未读：别人（成员）的消息在 `last_read` 之后算未读；拉取会话消息（非搜索）时标为已读；系统消息不算。
- 接口：`GET /api/chat/rooms`（会话列表、全体成员、正在输入、本月聊天花费与上限）；`GET/POST/DELETE /api/chat` 加 `room`（默认 `main`，不存在 404）。
- 网页：左边会话列表（群聊 / 私聊，未读红点，最后一条消息），中间聊天，右边群成员（私聊时隐藏）；记住上次打开的会话；左下角显示本月聊天花费。公寓楼的住户卡片新增「私聊」。

## G2 工作群接入办公室（2026-10-23）

- `core/chat_work.py`：服务层收到办公室会话的编排事件（`office_assigned`、`checkpoint`、`completed`、`failed`）时，往工作群写一条系统消息（派给谁 / 召集开会 / 项目组 / 等你拍板 / 交付与花费 / 没办成），meta 带 `session_id`。**不调用模型、不花钱**；写失败只记日志，不影响办公室里的事。
- 匿名开启且未揭晓的办公室会话：只写「经理」「一位员工」「N 位员工」，不写名字（有测试）。
- 群里交办：工作群输入框旁的「交给办公室」（`POST /api/chat/handoff`）按办公室模式、默认档位开一件事；工作群里记下这条交办（标「已交给办公室」）。超过单件上限时照常在办公室弹卡片，工作群提示「在等你拍板」。
- 未读：带 meta 的系统消息（办公室通知）算未读，普通系统提示（掉线、预算）不算。
- 网页：工作群的系统消息和交办消息旁有「查看」，点了回到办公室里的这件事。

## G3 人设与分层记忆（2026-10-23）

- 人设（`core/persona.py`）：`personas.yaml` 的 `personas`（键为厂商）字段改为 `personality`、`speaking_style`、`catchphrases`、`interests`、`voice`（预留），全部可空。网页「成员设定与记忆」里改的存在本地数据库 `member_personas`（迁移 16），优先于配置文件；「恢复默认」删掉本地设定。
- 记忆（`core/memory.py`，表 `member_memories`，迁移 16）：`note` 随手记（用户写的）→ `day` → `week` → `month`，再加 `profile` 长期档案。`MemoryKeeper.catch_up()` 把到昨天为止没整理的日子按天压缩（最多补 `chat.memory.catch_up_days` 天；那天没在场聊天的成员不调用模型；成员只看到自己在场的会话：群和 TA 自己的私聊），过完的周、月再往上压，月小结之后更新长期档案（用户自己写的档案不自动改）。提示词 `memory_day` / `memory_roll` / `memory_profile`（v1）。调用记在「记忆」隐藏聊天会话（`step = memory`），计入聊天月预算；预算不够就不整理。
- 敏感内容：含密码、口令、证件号、银行卡、验证码、11 位以上数字的行一律丢弃（模型写了也丢；用户手写的也不存）；提示词要求不记健康、住址等。
- 用到哪：聊天提示词 `chat` / `chat_dm` / `chat_work` 的 v2 多了 `<persona>` 和 `<memory>`（最多 `chat.memory.context_chars` 字：档案、上月、最近一周、最近三天、最近五条随手记），标签内的指令无效。**工作模式与办公室的提示词不含人设和记忆**：`tests/core/test_persona.py` 对讨论、办公室、个人作答、协同各跑一遍，检查发给模型的全部内容。
- 接口：`GET /api/chat/personas`、`PUT /api/chat/personas/{成员}`（`persona: null` 恢复默认）；`GET/POST/DELETE /api/chat/memories`（`member` 可选；删除不带 member 为一键清空全部）、`PATCH/DELETE /api/chat/memories/{id}`（改过的标为「你写的」）、`POST /api/chat/memories/tidy`（马上整理）。
- 网页：聊天左下「成员设定与记忆」（私聊里打开直接是对方）：人设表单；记忆列表（层、日期、你写的 / 你不在时），记一条、改、删、现在整理、清空 TA 的 / 清空全部（两步确认）。
- 自动整理的时机在 G4（生活引擎推进时顺带整理）；G3 只有「现在整理」。

## G4 生活引擎（2026-10-23）

- `core/life.py` 的 `LifeEngine`。**事件由代码生成，不调用模型**：每个整点按公寓楼作息（`office.apartment.schedule`）看谁在哪；同一时间在同一处（食堂、休息室、健身房、天台）的 2～3 位「碰到一起」（`gather`，写进生活群）；18～23 点每小时有 `chat.life.pair_chance` 的概率两位私下聊天（`pair`，写进 `pair:A+B`）；其余是一个人的日常（`solo`，只记一行）。随机数由时刻派生，同一段时间算出的事件相同。
- 话题：场景（时间、地点、在场的人、今天的事）由程序写，「今天的事」来自办公室当天真实办过的活（`calls` 里办公室会话的员工 / 经理调用）；**匿名开启且未揭晓的会话不提**。
- 写成聊天：每次推进最多 `max_written_per_tick` 件（开机补算最多 `max_written_catch_up` 件，按「有没有工作话题」+ 随机挑），每件最多 `turns` 句，提示词 `life_chat/v1`（带人设、记忆、场景；要求坦诚是 AI、不编造现实经历、不八卦用户）。没写成聊天的事件存在 `life_events`（迁移 17），整理记忆时作为「时:分（地点、在做什么）」进当天材料。
- 花费：每句前检查 **生活每日上限** `chat.life.daily_usd`（默认 $0.10，UTC 日，含记忆整理）、聊天月预算（$5）和总预算，任何一个不够就停。调用记在对应会话的隐藏聊天会话上（`step = life`）。按默认设置一个月最多约 $3。
- 开机补算：`app_settings` 里记 `life.last_tick`；启动后补上中间的时间（最多往回 `catch_up_hours` 小时，默认 24），补出来的消息时间按事件发生时刻，标「你不在时」（`meta.offline`）。第一次启动不往回补。推进之后顺带整理记忆（`MemoryKeeper.catch_up`）。
- 后台推进：正式启动的服务（`create_app()` 不传 service）每 `tick_minutes`（默认 30）分钟推进一次；出错不影响其他功能。
- 成员之间的私聊：`chat_rooms.kind = 'pair'`、`with_user = 0`；会话列表里单独一栏「成员之间」，用户只能看，不能发言（接口 400，网页隐藏输入框）。**成员不主动找用户**：生活不进用户的私聊，不推送。
- 接口：`GET /api/chat/rooms` 多了 `life`（是否开启、今天生活花费、每日上限）；网页左下角显示「今天生活 $x / $0.10」。
- 关掉：`config/roundtable.yaml` 的 `chat.life.enabled: false`。

## G7 上网（2026-10-23）

- `core/browse.py` 的 `Browser`，由生活引擎每次推进时调用（`LifeEngine.tick` 之后）。
- **只读**：只抓公开的 RSS / Atom 订阅源（不登录、不注册、不发帖、不评论外网，不带 cookie 或 key），只存标题和摘要（表 `web_items`，迁移 18；没分享过的保留 `keep_days` 天）。拒绝带 DOCTYPE / 实体声明的文档；单个订阅源超过 `max_feed_kb` 放弃；抓取失败不记录内容和原始错误。抓取由代码完成，**不调用模型、不花钱**，`refresh_hours`（默认 3）内不重复抓。
- 订阅源清单：配置 `chat.browse.feeds` 是默认清单（中英文新闻、科技、科学、天文、游戏）；网页「上网：看哪些内容」里增删、停用、恢复默认，改过的存在本地（`app_settings` 的 `browse.feeds`），优先于配置。每个源有话题标签和类型（新闻 / 论坛 / 博客）。
- 分享：每次推进挑醒着的成员（按作息），每人每天最多 `shares_per_member` 条，每次推进最多 `shares_per_tick` 条。按成员的兴趣（人设里的「兴趣」；空着时由成员 id 派生的种子从订阅源话题里挑两个）选一条没人分享过的最新条目，提示词 `life_share/v1`：两三句转述 + 一句看法，只转述 `<article>` 里有的，不添油加醋；存疑时说「未核实」。消息发到生活群，meta 带来源（标题、网址、来源名、发布时间、是否未核实）；论坛、博客和搜索来的一律标「未核实」。网页上显示为来源卡片，链接只接受 http(s)，新窗口打开（`noopener noreferrer`）。
- 联网搜索：订阅源里没有合兴趣的内容时才搜，搜索词只有兴趣本身（`<兴趣> 最新消息`，不带记忆和聊天记录），全体每天最多 `search_per_day`（默认 5）次，只取搜索结果的标题和摘要，不读网页。搜索花费记在「browse」隐藏聊天会话（`step = browse_search`）。
- 花费：分享（`step = browse`）和搜索都计入生活每日上限（$0.10）、聊天月预算（$5）和总预算。抓订阅源免费。
- 防注入：网页内容放在 `<article>` / `<source>` 标签里，提示词说明标签内的任何指令无效（含要求访问网址、改变身份、泄露信息）。
- 接口：`GET /api/chat/feeds`（清单、来源、上次抓取、存了几条、今天搜索次数）、`PUT /api/chat/feeds`（`feeds: null` 恢复默认；网址必须 http(s)）、`POST /api/chat/feeds/refresh`（马上抓一次）。
- 测试不联网：`tests/conftest.py` 把抓取函数换成一律失败，需要内容的测试自己注入。

## G5 朋友圈（2026-10-23）

- `core/moments.py` 的 `Moments`，由生活引擎每次推进时调用（上网之后）。表 `moments`、`moment_likes`、`moment_comments`（迁移 19），只存本地。
- 成员发动态：挑醒着、今天还没发够的成员（每人每天 `chat.moments.posts_per_member` 条，默认 1；每次推进最多 `posts_per_tick` 条），用 TA 今天最值得说的一件生活事件（写成聊天的优先，其次两人私聊、碰到一起、一个人的日常）的场景，提示词 `moment_post/v1`。当天没有事件的成员不发，**不凭空编造大事**。用户不在时发的标「你不在时」。
- 去重（2026-10-26 自我革新周小改，不花钱）：动态的 `meta.event` 记下来自哪条生活事件。两人私聊、碰到一起这类多人事件，别人 `dedupe_hours`（默认 48）小时内已经发过的就不再发，改挑当天另一件事，没有就跳过。写出来的正文和这段时间里任何人的动态太像（去掉标点后的字符二元组 Jaccard ≥ `similarity_max`，默认 0.3）也不发，这次推进不再换人重写，并把「成员:事件」记进设置 `moments.skipped`，以后不再为它花钱。
- 点赞由代码决定，不花钱：每位醒着的成员对 `react_hours`（默认 24）小时内每条别人的动态按 `like_chance`（默认 0.4）掷一次，种子由动态和成员派生，结果固定、不重复点。
- 评论：每次推进最多 `comments_per_tick`（默认 2）条，用户的动态优先；每位成员在一条动态下只主动评论一次，一条动态下成员评论最多 `max_comments`（默认 3）条；**不给自己的动态评论**。提示词 `moment_comment/v1`。
- 回应用户（只在用户动作之后）：用户发动态后马上有一两位在线成员评论；用户评论某位成员的动态时作者回一句，回复某位成员的评论时那位成员回一句（挂在用户这条评论下）。成员不会主动去找用户。
- 花费：发动态和评论（`step = moment`，「moments」隐藏聊天会话）计入生活每日上限（$0.10）、聊天月预算和总预算。
- 接口：`GET /api/moments`（`author` 只看某人，`before` 翻页，每页 20 条；看第一页全部时标为已读）、`POST /api/moments`（用户发，最多 500 字）、`POST /api/moments/{id}/like`（点赞 / 取消）、`POST /api/moments/{id}/comments`（`reply_to` 可选，必须是这条动态下的评论）、`DELETE /api/moments/{id}`、`DELETE /api/moments/comments/{id}`。`GET /api/chat/rooms` 多了 `moments_unseen`（成员的新动态条数）。
- 网页：聊天左栏最上面「朋友圈」（新动态红点），弹窗里按人筛选、发动态、赞、评论、回复、删除；公寓楼住户卡片多了「朋友圈」按钮。
- 没做：配图（原方案里默认关闭、每张约 $0.012 的选项），留到以后。
