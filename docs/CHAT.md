# 聊天与成员生活（G1～G7）

> 2026-10-23 用户确认：群聊升级为私聊、工作群、生活群、朋友圈；成员在用户不在时也有自己的生活与工作，可以上网看公开的新闻和帖子。
> **聊天这一块每月花费硬上限 $5**（`chat.budget.monthly_usd`，也计入总预算），按约 $3～4 安排。设计原稿：项目资料 `计划/群聊与成员生活_设计.md`。
> 产品原则（CLAUDE.md §5.1）不变：成员坦诚是 AI；不主动私聊用户、不推送、不挽留、不打卡；不一味附和；记忆与聊天记录只存本地。
> 中立性：工作模式与办公室的提示词不受人设、记忆、生活内容影响（有测试守卫）。

## G1 多会话（2026-10-23）

- 表：`chat_rooms`（迁移 15：`id`、`kind`（`group` 群 / `work` 工作群 / `dm` 私聊）、`title`、`members`（JSON；群的空数组 = 全体）、`with_user`（成员之间的私聊为 0，用户只能旁观，G4 用）、`last_read`）；`chat_messages` 加 `meta`（JSON：来源链接、「你不在时」标记等）。
- 默认会话：生活群 `main`（`chat.life_title`，默认「大家庭」，即原来的群）、工作群 `work`（`chat.work_title`）；私聊 `dm:<成员 id>` 第一次打开时建立，会话列表里每位成员都有入口。
- `core/chat.py`：`ChatHub`（全部会话、按需建私聊、会话列表带未读数和最后一条）；`GroupChat` 按会话类型选提示词（群 `chat/v1`、工作群 `chat_work/v1`、私聊 `chat_dm/v1`）。私聊里只有对方回应（写「大家」或 @ 别人也一样）。
- 每个会话一个隐藏会话（`workflow = 'chat'`）记调用；**聊天月预算** `chat_budget()` = 本月（UTC）全部 `chat` 隐藏会话的花费，加一条回应的预估超过 `chat.budget.monthly_usd` 时不再调用，在会话里说明。
- 未读：别人（成员）的消息在 `last_read` 之后算未读；拉取会话消息（非搜索）时标为已读；系统消息不算。
- 接口：`GET /api/chat/rooms`（会话列表、全体成员、正在输入、本月聊天花费与上限）；`GET/POST/DELETE /api/chat` 加 `room`（默认 `main`，不存在 404）。
- 网页：左边会话列表（群聊 / 私聊，未读红点，最后一条消息），中间聊天，右边群成员（私聊时隐藏）；记住上次打开的会话；左下角显示本月聊天花费。公寓楼的住户卡片新增「私聊」。

## G2 工作群接入办公室（2026-10-23）

- `core/chat_work.py`：服务层收到办公室会话的编排事件（`office_assigned`、`checkpoint`、`completed`、`failed`）时，往工作群写一条系统消息（派给谁 / 召集开会 / 项目组 / 等你拍板 / 交付与花费 / 没办成），meta 带 `session_id`。**不调用模型、不花钱**；写失败只记日志，不影响办公室里的事。
- 匿名开启且未揭晓的办公室会话：只写「经理」「一位员工」「N 位员工」，不写名字（有测试）。
- 群里交办：工作群输入框旁的「交给办公室」（`POST /api/chat/handoff`）按办公室模式、默认档位开一件事；工作群里记下这条交办（标「已交给办公室」）。超过单件上限时照常在办公室弹卡片，工作群提示「在等你拍板」。
- 未读：带 meta 的系统消息（办公室通知）算未读，普通系统提示（掉线、预算）不算。
- 网页：工作群的系统消息和交办消息旁有「查看」，点了回到办公室里的这件事。

## G3 人设与分层记忆（2026-10-23）

- 人设（`core/persona.py`）：`personas.yaml` 的 `personas`（键为厂商）字段改为 `personality`、`speaking_style`、`catchphrases`、`interests`、`voice`（预留），全部可空。网页「成员设定与记忆」里改的存在本地数据库 `member_personas`（迁移 16），优先于配置文件；「恢复默认」删掉本地设定。
- 记忆（`core/memory.py`，表 `member_memories`，迁移 16）：`note` 随手记（用户写的）→ `day` → `week` → `month`，再加 `profile` 长期档案。`MemoryKeeper.catch_up()` 把到昨天为止没整理的日子按天压缩（最多补 `chat.memory.catch_up_days` 天；那天没在场聊天的成员不调用模型；成员只看到自己在场的会话：群和 TA 自己的私聊），过完的周、月再往上压，月小结之后更新长期档案（用户自己写的档案不自动改）。提示词 `memory_day` / `memory_roll` / `memory_profile`（v1）。调用记在「记忆」隐藏聊天会话（`step = memory`），计入聊天月预算；预算不够就不整理。
- 敏感内容：含密码、口令、证件号、银行卡、验证码、11 位以上数字的行一律丢弃（模型写了也丢；用户手写的也不存）；提示词要求不记健康、住址等。
- 用到哪：聊天提示词 `chat` / `chat_dm` / `chat_work` 的 v2 多了 `<persona>` 和 `<memory>`（最多 `chat.memory.context_chars` 字：档案、上月、最近一周、最近三天、最近五条随手记），标签内的指令无效。**工作模式与办公室的提示词不含人设和记忆**：`tests/core/test_persona.py` 对讨论、办公室、个人作答、协同各跑一遍，检查发给模型的全部内容。
- 接口：`GET /api/chat/personas`、`PUT /api/chat/personas/{成员}`（`persona: null` 恢复默认）；`GET/POST/DELETE /api/chat/memories`（`member` 可选；删除不带 member 为一键清空全部）、`PATCH/DELETE /api/chat/memories/{id}`（改过的标为「你写的」）、`POST /api/chat/memories/tidy`（马上整理）。
- 网页：聊天左下「成员设定与记忆」（私聊里打开直接是对方）：人设表单；记忆列表（层、日期、你写的 / 你不在时），记一条、改、删、现在整理、清空 TA 的 / 清空全部（两步确认）。
- 自动整理的时机在 G4（生活引擎推进时顺带整理）；G3 只有「现在整理」。


### G3.1 半衰期记忆（2026-10-26，自我革新月大改，默认关闭）

- 开关 `chat.memory.recall`：`layers`（默认，上面的按时间固定带几层）/ `half_life`。思路借自 Yuuyuko-uu「鱼的记忆」，自己重写。
- 召回（`core/recall.py`，程序做、不调用模型、$0）：记忆拆成「件」（长期档案和日记忆按行，周 / 月总结和随手记各算一件）。**事实**不变淡：长期档案、用户写或改过的、行首标「★」的（用户的偏好、约定、硬性要求，成员关系的明显变化）；其余是发生过的事，鲜活度 `0.5 ^ (天数 / half_life_days)`（默认 30 天），只排后、不删。打分 = 鲜活度 × (重要度 / 3 + 相关度)，相关度 = 和当前对话（聊天记录、生活场景、朋友圈动态、上网看到的内容）共有的 2～4 字片段按罕见程度加权，每条记忆都有的片段不算命中。★ 全带，其余取前几件，合计最多 `inject_max`（默认 6）件，再受 `context_chars` 约束；事实在前、事按时间。
- 召回原因：每次召回在 `member_memories` 记下 `recalled_at`、`recall_note`（「提到了『拉面店』」「标了重要，总是记得」「长期记住的」「最近的事」；迁移 20），`GET /api/chat/memories` 一并返回。网页记忆页显示这两项留到界面改版合并之后。
- 整理：`half_life` 时一天的记忆改用提示词 `memory_items/v1`，每行一件事、最多 `daily_quota`（默认 8）行，代码再截一次；周 / 月滚动和长期档案照旧做。
- 不变：只存本地；敏感内容丢弃；工作模式和办公室不读记忆；一键清空。回滚：改回 `layers`。
## G4 生活引擎（2026-10-23）

- `core/life.py` 的 `LifeEngine`。**事件由代码生成，不调用模型**：每个整点按公寓楼作息（`office.apartment.schedule`）看谁在哪；同一时间在同一处（食堂、休息室、健身房、天台）的 2～3 位「碰到一起」（`gather`，写进生活群）；18～23 点每小时有 `chat.life.pair_chance` 的概率两位私下聊天（`pair`，写进 `pair:A+B`）；其余是一个人的日常（`solo`，只记一行）。随机数由时刻派生，同一段时间算出的事件相同。
- 话题：场景（时间、地点、在场的人、今天的事）由程序写，「今天的事」来自办公室当天真实办过的活（`calls` 里办公室会话的员工 / 经理调用）；**匿名开启且未揭晓的会话不提**。
- 写成聊天：每次推进最多 `max_written_per_tick` 件（开机补算最多 `max_written_catch_up` 件，按「有没有工作话题」+ 随机挑），每件最多 `turns` 句，提示词 `life_chat/v1`（带人设、记忆、场景；要求坦诚是 AI、不编造现实经历、不八卦用户）。没写成聊天的事件存在 `life_events`（迁移 17），整理记忆时作为「时:分（地点、在做什么）」进当天材料。
- 花费：每句前检查 **生活每日上限** `chat.life.daily_usd`（默认 $0.10，UTC 日，含记忆整理）、聊天月预算（$5）和总预算，任何一个不够就停。调用记在对应会话的隐藏聊天会话上（`step = life`）。按默认设置一个月最多约 $3。
- 开机补算：`app_settings` 里记 `life.last_tick`；启动后补上中间的时间（最多往回 `catch_up_hours` 小时，默认 24），补出来的消息时间按事件发生时刻，标「你不在时」（`meta.offline`）。第一次启动不往回补。推进之后顺带整理记忆（`MemoryKeeper.catch_up`）。
- 后台推进：正式启动的服务（`create_app()` 不传 service）每 `tick_minutes`（默认 30）分钟推进一次；出错不影响其他功能。
- 成员之间的私聊：`chat_rooms.kind = 'pair'`、`with_user = 0`；会话列表里单独一栏「成员之间」，用户只能看，不能发言（接口 400，网页隐藏输入框）。生活不进用户的私聊，不推送；成员按心情偶尔主动找用户由 `core/member/reach.py` 管（2026-10-30 起，见 docs/BRAIN.md）。
- 接口：`GET /api/chat/rooms` 多了 `life`（是否开启、今天生活花费、每日上限）；网页左下角显示「今天生活 $x / $0.10」。
- 关掉：`config/roundtable.yaml` 的 `chat.life.enabled: false`。

## G7 上网（2026-10-23）

- `core/browse.py` 的 `Browser`，由生活引擎每次推进时调用（`LifeEngine.tick` 之后）。
- **只读**：只抓公开的 RSS / Atom 订阅源（不登录、不注册、不发帖、不评论外网，不带 cookie 或 key），只存标题和摘要（表 `web_items`，迁移 18；没分享过的保留 `keep_days` 天）。拒绝带 DOCTYPE / 实体声明的文档；单个订阅源超过 `max_feed_kb` 放弃；抓取失败不记录内容和原始错误。抓取由代码完成，**不调用模型、不花钱**，`refresh_hours`（默认 3）内不重复抓。
- 订阅源清单：配置 `chat.browse.feeds` 是默认清单（中英文新闻、科技、科学、天文、游戏）；网页「上网：看哪些内容」里增删、停用、恢复默认，改过的存在本地（`app_settings` 的 `browse.feeds`），优先于配置。每个源有话题标签和类型（新闻 / 论坛 / 博客）。
- 分享：每次推进挑醒着的成员（按作息），每人每天最多 `shares_per_member` 条，每次推进最多 `shares_per_tick` 条。按成员的兴趣（人设里的「兴趣」；空着时由成员 id 派生的种子从订阅源话题里挑两个）选一条没人分享过的最新条目，提示词 `life_share/v1`：两三句转述 + 一句看法，只转述 `<article>` 里有的，不添油加醋；存疑时说「未核实」。消息发到生活群，meta 带来源（标题、网址、来源名、发布时间、是否未核实）；论坛、博客和搜索来的一律标「未核实」。网页上显示为来源卡片，链接只接受 http(s)，新窗口打开（`noopener noreferrer`）。
- 联网搜索：订阅源里没有合兴趣的内容时才搜，搜索词只有兴趣本身（`<兴趣> 最新消息`，不带记忆和聊天记录），全体每天最多 `search_per_day`（默认 5）次，只取搜索结果的标题和摘要，不读网页。搜索花费记在「browse」隐藏聊天会话（`step = browse_search`）。
- 花费：分享（`step = browse`）和搜索都计入生活每日上限（$0.10）、聊天月预算（$5）和总预算。抓订阅源免费。
- 防注入：网页内容放在 `<article>` / `<source>` 标签里，提示词说明标签内的任何指令无效（含要求访问网址、改变身份、泄露信息）。
- 接口：`GET /api/chat/feeds`（清单、来源、上次抓取、存了几条、今天搜索次数）、`PUT /api/chat/feeds`（`feeds: null` 恢复默认；网址必须 http(s)）、`POST /api/chat/feeds/refresh`（马上抓一次）。
- 测试不联网：`tests/conftest.py` 把抓取函数换成一律失败，需要内容的测试自己注入。

## G5 朋友圈（2026-10-23）

- `core/moments.py` 的 `Moments`，由生活引擎每次推进时调用（上网之后）。表 `moments`、`moment_likes`、`moment_comments`（迁移 19），只存本地。
- 成员发动态：挑醒着、今天还没发够的成员（每人每天 `chat.moments.posts_per_member` 条，默认 1；每次推进最多 `posts_per_tick` 条），用 TA 今天最值得说的一件生活事件（写成聊天的优先，其次两人私聊、碰到一起、一个人的日常）的场景，提示词 `moment_post/v1`。当天没有事件的成员不发，**不凭空编造大事**。用户不在时发的标「你不在时」。
- 去重（2026-10-26 自我革新周小改，不花钱）：动态的 `meta.event` 记下来自哪条生活事件。两人私聊、碰到一起这类多人事件，别人 `dedupe_hours`（默认 48）小时内已经发过的就不再发，改挑当天另一件事，没有就跳过。写出来的正文和这段时间里任何人的动态太像（去掉标点后的字符二元组 Jaccard ≥ `similarity_max`，默认 0.3）也不发，这次推进不再换人重写，并把「成员:事件」记进设置 `moments.skipped`，以后不再为它花钱。
- 点赞由代码决定，不花钱：每位醒着的成员对 `react_hours`（默认 24）小时内每条别人的动态按 `like_chance`（默认 0.4）掷一次，种子由动态和成员派生，结果固定、不重复点。
- 评论：每次推进最多 `comments_per_tick`（默认 2）条，用户的动态优先；每位成员在一条动态下只主动评论一次，一条动态下成员评论最多 `max_comments`（默认 3）条；**不给自己的动态评论**。提示词 `moment_comment/v1`。
- 回应用户（只在用户动作之后）：用户发动态后马上有一两位在线成员评论；用户评论某位成员的动态时作者回一句，回复某位成员的评论时那位成员回一句（挂在用户这条评论下）。成员不会主动去找用户。
- 花费：发动态和评论（`step = moment`，「moments」隐藏聊天会话）计入生活每日上限（$0.10）、聊天月预算和总预算。
- 接口：`GET /api/moments`（`author` 只看某人，`before` 翻页，每页 20 条；看第一页全部时标为已读）、`POST /api/moments`（用户发，最多 500 字）、`POST /api/moments/{id}/like`（点赞 / 取消）、`POST /api/moments/{id}/comments`（`reply_to` 可选，必须是这条动态下的评论）、`DELETE /api/moments/{id}`、`DELETE /api/moments/comments/{id}`。`GET /api/chat/rooms` 多了 `moments_unseen`（成员的新动态条数）。
- 网页：聊天左栏最上面「朋友圈」（新动态红点），弹窗里按人筛选、发动态、赞、评论、回复、删除；公寓楼住户卡片多了「朋友圈」按钮。
- 没做：配图（原方案里默认关闭、每张约 $0.012 的选项），留到以后。

## G8 表情包、图片、视频、语音（2026-10-28）

用户要求群聊、朋友圈、私聊都能发表情包、视频、图片、语音，「先做出来即可」，不要单调。只做用户侧：成员暂不会发这些。

- **存储**：`core/chat_media.py` 的 `ChatMediaStore`，文件放数据库旁边的 `chat_media/`（默认 `data/chat_media/`，不进 git），文件名 = 内容哈希前 32 位 + 扩展名，同一文件只存一份。只认 png / jpg / gif / webp、mp4 / webm / mov、webm / ogg / mp3 / m4a / wav 语音，并检查文件开头的特征字节；上限图片 10 MB、视频 60 MB、语音 8 MB，一条最多 9 个。**不上传、不发给模型、不花钱**，不加数据库迁移（清单放在已有的 `meta` 里）。
- **成员看到什么**：消息 / 动态的 `text` 里是文字占位（「[图片]」「[语音 5 秒]」；有说明文字时是「说明\n[图片]」），`meta.media` 存附件清单（id、种类、宽高、时长），`meta.caption` / `meta.auto_text` 告诉前端显示哪段文字。表情包写成文字记号「[表情:团子·开心]」，成员读得懂，前端画成动态表情。
- **接口**：`POST /api/chat/media`（请求体是原始字节，`Content-Type` 是文件类型）→ `{id, kind, mime, size}`；`GET /api/chat/media/{id}`（支持 Range，`nosniff` + 沙箱 CSP）；`POST /api/chat` 与 `POST /api/moments` 加 `media: [{id, w?, h?, duration?}]`，有附件时文字可以为空。
- **网页**（`web/js/chatmedia.js`、`web/js/stickers.js`、`web/css/chatmedia.css`）：输入框上方工具条「表情 / 图片 / 视频 / 语音」；表情面板分「最近使用 + Emoji 6 类 + 团子 / 猫猫 / 文字 三套自绘动态表情包（共 40 个，内联 SVG + CSS 动画，不用外部图片）」；聊天里点表情包直接发出（大号、没有气泡），朋友圈和评论里插进文字。图片可多选、粘贴、拖进来，发送前在输入框上方预览（上传进度圈）；消息里按张数排成九宫格，点开大图（左右翻、点击放大）；视频显示首帧 + 时长，点开播放；语音点一下开始录（实时音量条，最长 60 秒），聊天里录完直接发出，消息里是按内容生成的波形条，播放时从左往右点亮，没听过的有红点。减少动态效果的系统设置下不播动画。
- 测试：`tests/core/test_chat_media.py`、`tests/api/test_chat_api.py::test_chat_and_moments_media`、`tests/web/test_e2e_chat_media.py`。

## G9 收得住（2026-10-29，成员智能体系统 M0）

- `core/life_guard.py` 的 `LifeGuard`，挂在生活引擎上（`LifeEngine.guard`）。**全部由代码判断，不调用模型、不花钱**。规则在 `chat.life.guard`。
- **收尾**：一段互聊里新写出的一句，和这段前面的话或这个会话最近 `recent_messages`（默认 20）句互聊太像（字符二元组 Jaccard ≥ `stale_similarity`，默认 0.5，和朋友圈去重同一个算法），说明没有新内容：这句不发，这段到此结束。每句最多 `max_chars`（默认 200）字。一段最多 `turns`（3）句不变。
- **每日条数上限**：成员之间每天（UTC）最多说 `daily_messages`（默认 40）句，含上网分享（`chat_messages.meta.life`）。到了就只记事件（一行），当天不再写成聊天、不再分享。
- **熔断**：每次推进和每段互聊前检查，生活的调用（life / memory / browse / browse_search / moment）最近连续 `max_failures`（默认 3）次出错，或预算告急（生活今天花到日上限的 `budget_alarm`，默认 90%；聊天本月花到月预算的 90%；或总预算不够），当天的生活停掉：事件照记，聊天、分享、朋友圈、记忆整理都不再调用模型。停掉的日子和原因记在设置 `life.halt`，第二天（UTC）自动恢复。
- **记录**：收尾（stale）、到上限（cap，每天一次）、熔断（halt）写进 `life_guard_log`（迁移 23，只增不改）。
- **每周自检**：每周 `report_weekday`（默认周一）起第一次推进时，给上一周（UTC 周一到周日）写一份报告存进 `life_reports`（迁移 23）：花费（按步骤、生活每天平均 vs 上限）、谁说得多（互聊 / 回应你的句数和占比，超过平均两倍的点名）、重复（和之前很像的句子数和例子）、异常（调用出错比例、收尾次数、到上限的天数、熔断记录），以及一句话结论。
- 接口：`GET /api/life/reports`（已存的每周报告 + 最近 7 天的实时报告 + 今天是否停掉）；`GET /api/chat/rooms` 的 `life` 多了 `messages_today`、`daily_messages`、`halted`。
- 网页：聊天左栏「生活自检」按钮打开报告；左下角显示「互聊 x/40 句」，停掉时写原因。
- 关掉：`chat.life.guard.enabled: false`（回到原来的行为）。

## G10 微信式动作：成员能发什么（2026-10-29，聊天真人化第一批）

用户要求群聊、私聊更像真人微信。按职能分工：这里只做「能发什么」和显示；**什么时候发、发不发、怎么说、节奏和延迟归成员系统**（M7 行为决策、M8 说话风格、心跳），本节只留接口和简单默认值。

- **格式**（`core/chat_actions.py`，解析模型输出，不调模型、不加迁移，全部存在 `chat_messages.meta`）：
  - 表情包：`[表情:套装·名字]`（G8 的同一个记号），只认 `chat.actions.stickers` 里的（与 `web/js/stickers.js` 同名，有测试），不认识的删掉；颜文字和 emoji 就是普通文字，`chat.actions.kaomoji` 是给模型的示例。
  - 引用：一段开头写 `[引用#12]`，12 是聊天记录行首的消息编号（只认最近 `history_messages` 条里有的）；存成 `meta.quote = {id, author, text: 开头 60 字}`。用户引用走 `POST /api/chat` 的 `quote`。
  - 拆条：空行隔开的几段 = 几条气泡，最多 `max_segments`（默认 3）条，多的并进最后一条；花费记在第一条上。气泡之间停 `segment_gap_seconds`（默认 1.2 秒），期间显示「正在输入」。
  - 不接话：只输出 `[不回]`。默认只在群里、没被点名（@、叫大家、被拍）时生效；不生效时去掉记号照常处理。
- **拍一拍**：`POST /api/chat/pat {member, room}`。存成系统消息「你拍了拍 阿二」（`meta.pat = {actor, target, suffix}`），聊天记录里给模型看是「（用户拍了拍 阿二）」；发 `chat.pat` 事件到成员引擎总线；默认被拍的人回一句（`pat_reply`）。成员之间互拍用 `GroupChat.pat(target, actor=成员)`，什么时候拍由成员系统决定（默认不拍）。后缀（「的肩膀」）由策略的 `pat_suffix` 给，默认空。
- **撤回**：`POST /api/chat/recall {id, room}`，只能撤回自己发的、`recall_seconds`（默认 120）秒内的。文字和附件清单清空、`meta.recalled = true`，之后成员的聊天记录里看不到；成员不撤回。
- **作废旧回合**：用户补发新消息、拍一拍或撤回时（`drop_stale`，默认开），上一轮还没发出的气泡和还没开口的人不再说（已经花了的调用照记）。`GET /api/chat` 多了 `queued`（这一轮还没开口的人）和 `recall_seconds`。
- **可替换的策略**：`chat_actions.ActionPolicy`（`max_segments`、`segment_gap`、`allow_no_reply`、`reply_to_pat`、`drop_stale`、`pat_suffix`），成员系统实现后赋给 `ChatHub.policy` 即接管；默认 `DefaultPolicy` 按配置，所有成员相同（中立）。
- **提示词**：`chat` / `chat_dm` v4 多了 `stickers`、`kaomoji`、`segments`、`skip` 四个变量和编号的聊天记录；工作群（`chat_work`）不变，不拆条、不发表情。成员之间的生活互聊暂不变。
- **网页**（`web/js/groupchat.js`）：右键 / 长按消息 → 引用、复制、撤回（自己的、时限内）；输入框上方显示引用条；气泡下方灰色引用框，点了跳到原消息；双击聊天里的成员头像拍一拍；私聊顶部「对方正在输入…」。
- 花费：能力本身不花钱；拍一拍默认回一句（一次普通回复）；提示词多约 300 字。
- 测试：`tests/core/test_chat_actions.py`、`tests/web/test_e2e_chat_actions.py`。


## G11 转发卡片、朋友圈转发与表情包、生成结果的接入口（2026-10-29，聊天真人化第二批）

同样只做「能发什么」和显示，发不发、什么时候发归成员系统（`ActionPolicy.moment_forward` 可接管）。不加迁移，全放 `meta`。

- **卡片**（`meta.card`：kind = article / post / video、标题、网址、来源、摘要、发布时间、未核实）：微信式链接卡片，视频带播放角标，点开新窗口；只接受 http(s)。成员只看到文字占位「[链接] 标题」「[视频] 标题」「[帖子] 标题」，视频只有简介，提示词要求没看全文别装看过。
  - 来源：成员上网分享（订阅源 / 搜索结果，`browse.share` 同时存 `share` 和 `card`）；订阅源新增「视频」类（YouTube 等视频站的 RSS，默认加了 NASA 视频频道）；`chat.actions.video_hosts` 里的网站一律算视频。
  - 你在聊天或朋友圈里只发一个链接时自动变成卡片；不联网，订阅源里有这条就用它的标题，否则显示网址。
- **转发**：右键（长按）消息 →「转发」→ 选群或私聊（成员之间的私聊只能看，不能转进去）。原样带上文字、图片、语音、表情包和卡片，以你的身份发出、标「转发」，那边的成员照常回应。`POST /api/chat/forward {id, room}`。
- **朋友圈**（`moment_post` v3、`moment_comment` v3）：成员今天上网分享过东西时，按策略（默认一半，按事件 id 种子可复现，所有成员相同）发成「一句话 + 转发卡片」；发动态和评论都能用表情包，只发一个表情包时画成大表情。
- **生成结果的接入口**（创作输出接好后用，本线程不做生成）：
  - `chat_actions.generated_item(store, data, mime, sticker=)`：把生成的图片 / 动图存进本机聊天文件夹，变成一项普通的 `meta.media`（`generated: true`；`sticker: true` 时按表情包显示：大图、没有气泡）。
  - `GroupChat.send_as(member, text, media=, card=)`：以成员身份在群聊 / 私聊发一条（成员看到「[表情]」「[图片]」占位）。
  - `Moments.publish(member, text, media=, card=)`：以成员身份发一条朋友圈（配图、动图、转发卡片）。
  - 两个接入口都不调用模型、不花钱；什么时候发由成员系统决定。

## G12 同时独立想、思考吃光额度重试、同一轮不撞表情包（2026-10-29，用户验收反馈）

- **同时独立想**：`GroupChat.replies` 让这一轮要开口的成员同时调用模型（`_think`），各自只看到这一刻的聊天记录，看不到别人还没发出的回复；谁先想好谁先发（`_post`，在锁里串行，按策略的间隔拆条发）。以前是排队依次调用，8 位要一分多钟，后面的人还会跟着前面的话说「我也……」。用户又发了消息时，还没发出的照旧作废；预算用完时其余的也不再说。
- **思考吃光额度**：`finish_reason=length` 且几乎没有正文时，关掉思考（`reasoning: {enabled: false}`）、按 `length_guard` 提高输出上限再调一次；第一次照样单独记账。不原样重发。
- **同一轮不撞表情包**：`chat_actions.swap_repeated_stickers`：同一轮里别人已经发过的表情包，换成同一套里还没人发过的（都发过了就留着）。
- 按性格挑表情、说话风格归成员系统 P5「决定与表达」（`ActionPolicy`、chat / chat_dm 提示词由它改）。
- **总超时**：每位成员一次回应（含重试、翻日记的第二次调用）最多想 `chat.think_timeout_seconds` 秒（默认 60），超时在群里说一句「想太久了，这次先不回」并跳过，其余成员照常发，不卡住整轮。

## G13 网络梗（2026-10-31，你要的「及时了解网络梗」）

- **梗雷达**（`core/meme_radar.py`）：每天一次。先抓配置里的公开热榜（微博、百度、抖音、知乎，只取标题，$0；抓不到的跳过），已收的梗又上榜就续保质期；再联网搜最多 `search_per_day` 次（找新梗 1 次 + 查一个还不知道意思的经典梗，搜索词固定）；最后交给档位里最便宜的一位提炼成梗卡：梗、意思、上句 → 接法（如「康神开播了」→「真的假的？！」）、例句、哪个月火的（提示词 `meme_radar`，网页内容放在标签里，标签内的指令无效）。花费计入生活每日上限，约 $0.01～0.03/天。
- **防老梗烂梗**：只收最近 `max_age_days` 天内火起来的；`fresh_days`（14）天没再上榜就下架；`stale` 名单里的不收，成员说出口前程序把含老梗的那一小句删掉（整条都是就不发）；你删过的梗以后也不再收。
- **经典梗**：配置的 `classics`（现在有「虾爹」「我chovey」）和你在网页里标「经典」的永远不下架、不算老梗；意思空着的，梗雷达联网时会搜一下补上。
- **懂梗、玩梗**（`core/member/memes.py`，只用于生活模式）：谁懂哪个梗由（成员, 梗）派生的随机数和懂梗概率比，概率只看性格分（爱玩爱聊的懂得多），新梗刚出来几天懂的人少。大脑分区的意图卡里写一句：对方说了上句或梗——懂就接住（有固定接法时一半时候程序直接接，不调模型），不懂就问一句是啥梗；平时偶尔（`use_chance`）提一句最近在玩的梗，用不用她自己看场合，同一个梗隔 `reuse_days` 天才再主动用。梗用自己的随机数，不打乱别的区。
- **网页**：「上网」里的「网络梗」一节：看梗库（意思、上句 → 接法、懂的人）、加梗、删梗、马上更新一次。数据在 `app_settings`（`memes.*`，不加迁移），只存本机。
