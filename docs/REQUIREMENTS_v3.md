## 1. 核心方向

多个 AI 像真人学习小组一样完成作业：**先讨论分工是否合适，再分工、协作、互相纠错**，而不是各自答题或敷衍附和。作业可以跨学科（理科、文科、艺术、设计、音视频），产出可以是文字、图片、音频、动画、文档。

系统分两层：

| | 里层（统筹层） | 表层（作业层） |
|---|---|---|
| 职责 | 架构、统筹、推进、计划、记录 | 讨论、分工、制作、互相改进 |
| 风格 | **理性化**：结构化输出，只说事实和数字 | **拟人化**：有人设，像同学聊天 |
| 角色 | 统筹（规划 + 调度）、记录官 | 组员 |
| 界面位置 | 右侧面板 | 圆桌 + 群聊 |

## 3. 人设

### 3.1 两种模式（界面可切换，默认人设模式）
- **人设模式**：每个 AI 有昵称、性格、口头禅、专长标签，按各家 AI 的公认特点设定，界面显示是哪家模型。
- **匿名模式**：组员显示为「组员甲乙丙丁」，讨论结束后才能「揭晓身份」。

### 3.2 人设内容（写在 `config/personas.yaml`，可改）
- 小G：开朗自信的班长型优等生，什么活都能接，爱列 1-2-3，口头禅「当然可以！」
- 克劳德：温柔细致的文艺学姐，写作和审稿担当，常说「我想补充一点」，偶尔过分谨慎
- 双子：灵感多的艺术生，读图第一名，习惯拿出两个方向让人挑，说话爱带「～」
- 千问：较真的理科学霸，推导稳，专门抓科学错误
- 格罗克：嘴毒但效率极高的项目经理，进里层只说数字和结论
- 小鲸：深海学霸，话少记性好，值班记录只写事实

### 3.3 规则
- 性格只影响说话方式和思考角度，**不影响严谨性**。
- 里层成员保留昵称，但输出必须理性、结构化。
- **头像**：默认用原创字形徽章，不使用各厂商的品牌形象或网络同人角色图；用户可在「名册」里上传自己的头像图片替换（存在本地数据库）。
- **中立**：即使在人设模式下，发给模型的内容里各成员也只用代号（甲乙丙丁），不告诉模型谁是哪家，减少模型之间互相偏袒。界面上给用户显示人设。
- 输出中出现自报模型身份（「作为 GPT……」）时，在发给其他模型前遮蔽。

## 4. 协作机制（重点：不能敷衍）

### 4.1 先讨论分工
- 统筹按能力标签给出初步分工。
- **组员讨论这样分工是否合适**，可以提出调整（如「讲解稿和海报文案应该统一口径」「分镜我来写，让她专心画」）。
- 统筹根据讨论结果更新分工，再进入任务确认。

### 4.2 按领域分工 + 流水线协作
- 按作业涉及的领域分工：理科、文科、艺术、设计、音视频等。
- 支持流水线：**一人提供关键词 → 一人设计 → 一人改进 → 一人核对**。流水线在统筹的结构化计划里定义，界面显示每一环的负责人和状态。
- 共享产物（如「核心说法表」）：所有交付物从同一份标准表述取句子，避免口径不一。

### 4.3 防敷衍规则（写进组员提示词，并有代码检查）
- 每次发言必须包含**新内容**：新信息、具体修改建议、指出错误、提出问题、或交付产物。纯附和（「好的」「同意」）不单独成条，计为跳过本轮。
- 审稿、核对时必须给**具体位置和修改建议**，不能只说「挺好」。
- 鼓励实质性反驳：发现错误必须指出，被指出后要么改正要么给出理由。
- 统筹检测「连续多轮无新内容」时，主动点名或推进下一步。

### 4.4 结对核对（双重保证）
- 关键内容由两名组员**各自独立核对**，彼此看不到对方结果。
- **作者本人不参与核对自己的作品**；两名核对者尽量来自不同厂商。
- 结果交回里层比对：一致 → 通过；不一致 → 交组内讨论；仍无法解决 → 问用户。
- 结对强度跟档位挂钩：简单 = 不结对；中等 = 仅核心内容；完整 = 核心内容 + 主要交付物。

## 5. 多媒体：输入与输出

### 5.1 用户上传（输入）
- 支持：图片、音频、视频、PDF、Word、PowerPoint、Excel、txt / md / csv。
- 方式：回形针按钮 + 拖进聊天区；聊天里显示预览（图片缩略图、音视频播放器、文档名和大小）。
- 处理方式：
  - 图片 → 交给有 `vision` 标签的组员读取
  - 音频 → 先用转写模型转成文字，再交组员
  - 视频 → 抽关键帧 + 转写音轨后交组员
  - 文档 → 解析成文本（PDF / docx / pptx / xlsx）后交组员
- 上传的文件存档并进入「文件库」，记录官写入会议记录。

### 5.2 小组生成（输出）
| 产物 | 生成方式 | 格式 |
|---|---|---|
| 图片 / 海报 | 有 `image_gen` 标签的图像模型；或由模型写绘图代码渲染（更便宜，适合图表、示意图） | PNG |
| 音频 / 配音 | 有 `tts` 标签的语音模型 | MP3 / WAV |
| 动画 | **默认由模型写绘图代码逐帧渲染**（如 matplotlib / Pillow → MP4），不调用视频模型，省钱 | MP4 / WebM |
| 视频（真实画面） | 可选，配置里的视频模型，费用高，**每次必须先问用户** | MP4 |
| 文档 | Python 库生成 | DOCX / PDF / MD |
| 演示文稿 | Python 库生成 | PPTX |

- 每个产物有版本号（v1、v2…），改进后的新版本和旧版本都保留。
- 每个产物可预览、可下载，最终汇总成「交付物」清单。
- `config/models.yaml` 中新增能力标签：`vision`、`image_gen`、`tts`、`transcribe`、`video_gen`。没有对应模型时，界面明确提示该功能不可用。

## 6. 流程与用户参与

### 6.1 标准流程
1. 统筹读题 → 拆交付物和领域 → 初步分工 → 预估轮数、token、媒体费用
2. 组员讨论分工是否合适 → 统筹更新分工
3. **【确认点】任务确认**（同时提示可上传参考资料）
4. 按流水线分轮推进：讨论 → 制作 → 改进 → 结对核对
5. 汇总交付物 + 「讨论中做出的改进」清单
6. 匿名模式下揭晓身份

### 6.2 必须暂停询问用户的情况（其余时间不打扰）
1. **轮数**：预估 > 5 轮时，给出「简单 / 中等 / 完整」三档，附轮数和费用
2. **任务确认**：开始前
3. **决定性结果**：方向选择（如海报两种风格，附缩略图）、无法调和的分歧
4. **大额消耗**：下一步预估超过 token 阈值（默认 20k），或要调用付费媒体生成

确认卡片固定格式：**现状 / 选项 / 各选项代价 / 推荐**，按钮：选项、修改（可附文字）、停止。

### 6.3 用户随时插话
- 以「组长」身份在群聊发言，统筹把意见分派给最相关的组员，写入会议记录。
- 会话可暂停、关闭页面后恢复。

## 7. 记录官与省 token
- 会议记录每轮更新，包含：结论与决定、进度、**关键原文逐字保留**（由代码从原消息复制并校验，不靠记录官手抄）、未解决问题、用户意见、上传的资料。
- 组员只收到：当前会议记录 + 最近 2 轮原文 + 自己任务相关的上下文。
- 组员可请求「查原文」，从数据库取出完整发言。
- 发言长度上限默认 200 字（产物不受限），按需发言，无新内容就跳过。
- 里层用结构化短输出；支持的模型开启 prompt caching。
- 记录每次调用的 token、费用和媒体生成费，存库并在界面实时显示。

## 8. 界面（以 `docs/mockup.html` 为准）

**技术选择需要调整**：圆桌动画、拖拽上传、实时群聊、音视频预览用 Streamlit 实现很别扭。建议：
- 后端：**FastAPI**，用 SSE 或 WebSocket 推送实时消息
- 前端：基于 `docs/mockup.html` 改成真实页面（原生 JS 即可，不需要大型框架）
- 核心逻辑仍放在 `core`，不依赖任何 Web 框架，测试检查这一点

布局：
- **左：圆桌**。6 个座位围坐，发言者头像发光；金色箭头显示「谁把什么交给谁」；红色虚线表示结对独立作业；桌面中央显示当前阶段和动作；里层成员用方形头像
- **中：群聊**。消息带昵称、模型名（人设模式）、消息编号；附件内嵌预览；确认卡片内嵌；底部输入框 + 上传
- **右：里层面板**。标签页：分工流程 / 结对核对 / 会议记录（各版本）/ 文件库 / 用量（含 $100 预算条）/ 名册（人设、换头像）
- 顶部：人设 / 匿名切换、暂停 / 继续、累计 token 和费用
- 窄屏（手机）时三栏上下堆叠

## 9. 中立性规则（汇总）
- 所有组员使用同一份提示模板，只有人设字段不同。
- 发给模型的内容只用代号，不出现模型名或厂商名；自报身份遮蔽。
- 作者不核对自己的作品；结对核对者互不可见、尽量跨厂商；结果随机顺序呈现。
- 里层不兼任同场组员；统筹轮换。
- 按能力标签分工，标签由用户在配置中维护。
- 抽座位、分配人设（匿名模式）、结对、排序的随机种子存库，可复现。

## 10. 配置文件
- `config/models.yaml`：模型、provider、vendor、价格、能力标签（含 `vision` / `image_gen` / `tts` / `transcribe` / `video_gen`）
- `config/personas.yaml`：每个模型的昵称、性格、口头禅、专长，以及匿名代号池
- `config/roundtable.yaml`：座位数、轮数阈值、token 阈值、档位定义、发言上限、上下文轮数、防敷衍规则开关、流程步骤顺序、里层轮换规则
- `prompts/<role>/v<n>.md`：统筹、记录官、组员、审稿、核对等角色的版本化提示词

## 12. 默认值
1. 表层 4 个组员；里层统筹 1 + 记录官 1；共 6 个模型
2. 轮数阈值 5；token 询问阈值 20k / 步
3. 发言上限 200 字；上下文保留最近 2 轮
4. 默认档位：中等
5. 动画默认用代码渲染；真实视频生成默认关闭
6. 某组员失败：跳过并由同领域的其他组员接手；组员少于 2 人时暂停问用户
