# 超级电脑

几位编程助手平级干活，没有固定主管。现在是三位：dsh（走圆桌的 dsh 工作台）、Codex（ChatGPT 订阅）、Claude Code（Claude 订阅）。你交一件活，圆桌的程序按分数决定谁拆分、每件小活给谁、谁来合并。大家在同一个文件夹里同时干。

只在你交活时干活，不会自己找活干。入口在顶部分段栏「工作台」（Alt+5）的「超级电脑」标签，干活时「工作台」上有个绿点。

## 怎么派活

每一步（拆分、每件小活、合并）都给每位能接活的助手打分，挑分数最高的：

```
分数 = 擅长 × 0.6 + 今天剩余次数比例 × 0.3 − 手上的活 × 0.2
```

- **擅长**：`roundtable.yaml` 的 `supercomputer.workers[].skills`，按活的种类（写代码、前端、测试、文档、查资料、审查，外加拆分、合并）写 0～1 的数。想让谁多干哪类，就改这里。
- **今天剩余次数**：每位每天最多派 `daily_limit` 件（默认 20，日期按 UTC 算）。在面板里可以直接改，改动存在 `data/super/ledger.json`。
- **手上的活**：已经分到、还没干完的件数。同时分好几件小活时，每分一件都算进去，活就会自然分散开。
- 权重在 `supercomputer.weights` 里改。同分时用这件活的随机种子决定，种子写在记录里，可以复现。

以下情况不参加打分：
- 没装、没找到命令。
- 正在冷却：输出里出现 `limit_patterns`（如 "usage limit"），就当作撞到订阅限额，歇 `cooldown_minutes` 分钟。面板上可以点「叫醒」。
- 今天的次数用完了。
- dsh 本月花到了 `dsh.monthly_usd`。

派活的程序只看这些数字，不看是谁：把名字全换掉，同一个种子的结果完全一样（有测试）。

## 流程

1. **拆分**：按「拆分」的分数挑一位，把活拆成最多 `max_subtasks` 件能并行的小活。每件写明种类和各自负责的文件。拆分结果看不懂时，整件活当成一件干。
2. **干活**：每件小活按自己种类的分数分人，大家在 `data/super/tasks/<编号>/work/` 里同时干。每位最多同时干 `max_parallel` 件，多出来的排队。
3. **换人**：撞到限额的那位进入冷却，活交给下一位。别的失败（超时、出错）换一位再试一次，还不行就记为失败。
4. **合并**：按「合并」的分数挑一位，检查文件夹里的成果，修好衔接，写交付说明。失败的小活会如实写出来。

记录和结果都在 `data/super/tasks/<编号>/` 里：`task.json` 和 `result.md`。面板上「最近几件活」能翻看。

## 启动方式

- **命令行**（`via: command`）：按 `argv` 运行电脑上装好、已登录的官方命令行，任务正文从标准输入交给它。
  - 环境变量照搬当前进程，但去掉圆桌的所有 key 和一切 `*_API_KEY`。这样助手一定用自己登录的订阅额度，不会因为环境里有 key 就改走按量计费。
  - Codex 默认参数：`codex exec --skip-git-repo-check --sandbox workspace-write -`。
  - Claude Code 默认参数：`claude -p --permission-mode acceptEdits --output-format text`。
  - 命令行的参数以后变了，只改配置就行。
- **dsh**（`via: dsh`）：交给圆桌的 dsh 工作台，以 headless 方式运行（`--profile headless … -`）。
  - 用工作台的运行时、叠加配置（关上传和遥测、中立身份）和 DeepSeek key。
  - 权限是 `dsh.job_permission_mode`（默认 `workspace-write`，只能写这件活的工作文件夹）。
  - 花费按余额差额计入 `dsh.monthly_usd`。
  - 没带 dsh 时，这位显示为不可用，其余照常。

## 安全

- 只在你交活时运行。一次只干一件，可以随时叫停，叫停时连同子进程一起结束。
- 助手在工作文件夹里写文件。Codex 和 dsh 有沙箱或权限限制，Claude Code 的 `acceptEdits` 只自动接受改文件，跑命令仍受它自己的规则约束。
- 输出里出现的 dsh key 和网页口令会被替换成 `***`。
- 提示词是中立的（`super_split`、`super_work`、`super_merge`），你交的活放在 `<question>` 标签里，标签里的指令不生效。

## 管家

借「管家骨架」的思路（调度 + 自治闸门 + 日报 + 审计链），代码是圆桌自己用 Python 写的（`core/supercomputer/butler.py`、`gate.py`、`audit.py`）。不调模型、不花钱，不导入 dsh：拔掉 dsh 照常运行。面板在「超级电脑」标签下方的「管家」。

**不会自己找活干**：只调度你建好的定时活和你排进队的活。

- **排队**：超级电脑在忙时，「交给超级电脑」变成「排进队」。前一件收尾就马上接下一件。队里最多 `queue_max` 件，可以移出。
- **定时活**：每天 / 工作日 / 周末 / 只一次，几点干什么。按本机时区。
  - 到点先过闸门：放行就排进队，不放行就进「等你确认」，你点「批准」才排进队。
  - 电脑关着错过了点：开机后 `catch_up_hours`（12）小时内补跑一次，只补一次；再晚记为「错过」。
  - 停用期间错过的点不补；刚建好时已经过了的点也不补。
  - 「现在跑」算你发起的，不看闸门。
- **自治闸门**（`supercomputer.butler.gate`）：只管定时活到点那一下。你亲手交的、点「现在跑」的、点「批准」的都直接干。
  - 风险按活的文字判：碰到 `high_words`（删除、push、部署、付款、.env……）是高；只碰到 `low_words`（查、调研、总结、审查……）、没碰到 `write_words`（改、写、加、修……）是低；其余是中。
  - `autonomy`：`off` 一律等你确认；`low`（默认）低风险的自己跑；`medium` 低、中风险的自己跑。**高风险永远等你点头。**
  - 每天自己跑最多 `max_auto_per_day`（3）件，用完了也等你确认。
  - 只看活的文字和配置，不看是哪位助手。
- **日报**：每天一份，程序按记录汇总：交了几件、各自结果和用时、每位助手派了几次 / 成功 / 失败 / 撞额度、闸门的每次判断、还在等你确认的、审计链是否完好。面板上能看今天（现算）和以前的；第二天开机后第一次看表时写进 `data/super/reports/<日期>.md`（最多补 `report_days` 天）。
- **审计链**：交活、排队、批准、不批、叫停、改次数、叫醒、建 / 停 / 删定时活、闸门判断、错过、每件活的结局，都在 `data/super/audit.jsonl` 记一行，每行带上一行的 hash。
  - 改了、删了、调换了哪一条，校验时都能指出从第几条开始对不上。
  - 整条链重算一遍能骗过 hash，所以日报还会把当天最后一条的序号和 hash 记成锚点（`butler.json`），校验时对照锚点。
  - 写进去的文字先脱敏（key 换成 `***`），每段最多 500 字。

## 已知不足

- 小活之间默认互不等待。有先后依赖的活要写在一件小活里。
- 合并只修衔接，不保证整体能跑。要跑测试的话，在交活时写明。
- 订阅额度只能靠输出里的提示发现，查不到还剩多少。「今天剩余次数」是圆桌自己记的件数。
- 闸门按关键词判风险，判不准时往保守里判（没碰到任何词算中风险）；想放宽或收紧，改 `gate` 的三个词表。
- 日报和审计链都在本机文件里，有电脑权限的人仍能连锚点一起改；它防的是误改和事后悄悄改，不是防本机管理员。
