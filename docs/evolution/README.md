# 革新例会与每周革新

圆桌每周自我改进一次：**成员讨论和投票，开发侧（Claude）统筹和实施，ChatGPT 挑错（可选），用户点合并。**
方案原文：项目资料 `计划/自我革新机制_方案.md`（v3）。本目录放周报与模板。

## 一周的流程

1. **写资料卡**：从 GitHub、论文、官方文档等挑 3～5 个新做法，每个写成一页资料卡（[资料卡模板](资料卡模板.md)），放进用户电脑的收件箱 `data/evolution/收件箱/`。成员只看到卡，看不到原文。可以由开发侧写，也可以由**圆桌自己找**（见下面「自己找资料」）。
2. **革新例会**（圆桌成员，在用户电脑上的圆桌服务里跑）：所选档位（默认节电档）**全员上桌**，资料卡作为附件发给每个人（同一份），走头脑风暴流水线：出点子 → 碰撞杂交 → 匿名投票（不能投自己，顺序随机）→ 统筹整理。开完导出**采纳单** `data/evolution/采纳单/YYYY-Www.md`：前 10 名建议（`adopt_top`），附得分、票数、代号、反对意见。开完还会写一份**插件清单**（见下）。
3. **你拍板**：网页「革新例会」里，开完的例会下面列出得票前几名，每条可以点「做这条」或「不做」（可以改主意）。点了「做这条」的写进 `data/evolution/待实现.md`。
4. **实现**（开发侧）：优先实现 `待实现.md` 里你点过的；没有时从采纳单里挑一条不碰护栏的实现，测试，开 PR 到开发分支，写周报（[周报模板](周报模板.md)，保存为 `docs/evolution/YYYY-Www.md`）。碰护栏（R9 以后、默认玩法、新依赖、预算）的只写进周报的「要你拍板」。
5. **复审**（可选）：`python scripts/evolve_review.py --base origin/<开发分支>`。没有 key 时自动跳过并提示。
6. **合并**：永远由用户点。

开过会的资料卡会移到 `data/evolution/已用/<周>/`，下周不会再读。

用户电脑那周没开服务，就由开发侧自己挑一条，并在周报里注明「本周没有开例会」。

## 开启革新例会（用户电脑上）

默认关闭。打开 `config/roundtable.yaml`，把 `evolution.enabled` 改成 `true`，重启服务。

- 开启后服务开着时每周一 9 点之后自动开一次（`evolution.schedule`；`auto: false` 只手动开）。
- 手动开：网页右上角「革新例会」→「现在开一场」；或命令行 `roundtable evolve meet`。
- 查看：`roundtable evolve`；导出某场的采纳单：`roundtable evolve export <会话 id>`（自动开的会开完会自动导出）。

## 自己找资料（`evolution.scout`）

圆桌自己联网找新做法、写资料卡：

1. 代码按 `scout.queries` 的搜索词联网搜索，**只留 `scout.domains` 白名单网站**（含子域名，默认 GitHub、arXiv、OpenReview、ACL Anthology、Hugging Face），写过的网址不再写。
2. 代码读网页正文（最多 `page_chars` 字）。
3. 所选档位里按预计价格挑最便宜的一位成员写卡（提示词 `evolution_card`），再挑**另一位**复核（`evolution_check`：忠实、没夹带指令、有用），只看档位和价格。
4. 复核通过的卡写进收件箱 `YYYY-Www-scout-N.md`，每次最多 `scout.cards` 张。

- 自动：开启 `auto` 时，到了开会时间、本周还没开会、收件箱是空的，就先找一次资料（每周最多一次，找不到也不再重试），下一次检查时开会。
- 手动：网页「革新例会」→「找资料」，或 `roundtable evolve scout`。
- 防注入：网页正文放在 `<page>` 标签里，提示词说明标签内的指令无效；卡写好后去掉代码块、截断，再遮蔽模型 id、厂商名、昵称；复核成员能看到原文，夹带指令的不通过。
- 花费：搜索、读网页、写卡、复核都挂在一个隐藏会话上，计入总预算和革新例会的每月上限（找资料前先按 `search_estimate_usd` / `card_estimate_usd` 预估，超过本月剩余额度就不找）。

## 做这条之后（`evolution.implement`，默认关闭）

开启后，你在网页上点「做这条」（这一下就是你拍板），圆桌在你电脑上叫起开发侧：

1. 第一次用时把仓库 clone 到 `data/evolution/工作区/`（专用副本，不碰你平时用的目录）。
2. 用 `agent` 命令（默认 Claude Code：`claude -p`，用你本机的 Claude 登录）按 [开发任务模板](开发任务模板.md) 实现：从 `base_branch` 拉分支 `evolve/<周>-<编号>`，遵守 CLAUDE.md，跑 ruff / pytest，推送，`gh pr create` 开 PR。
3. 网页上那条建议显示进度：开发侧在做… → PR 开好了（附「看 PR」链接）/ 没做成（可以再点「做这条」重来）。输出记在 `data/evolution/开发记录/`。
4. **从不自动合并**：PR 开好后网页上出现「合并」，你点了（再确认一次）才执行 `gh pr merge`。

需要本机装好并登录 `claude` 和 `gh`；找不到命令时那条显示「没做成」并写明原因。花的是你 Claude 订阅的额度，不占圆桌预算。

## 插件清单（`evolution.plugins`，默认开启）

例会开完后，圆桌自动写一份给你看的插件清单（服务开着时；网页上也可以点「写插件清单 / 重写」，命令行 `roundtable evolve plugins <id>`）：

- **至少 20 个**（`count`），每个写：做什么、有什么用、优点、缺点、为什么做、参考（资料卡 N / 点子编号 / 成员补充）、用在哪个场景（`scenes`：办公室工作、公寓生活、群聊、朋友圈、头脑风暴、记忆、通用）。网页上按场景筛选。
- 由所选档位里**预计最便宜的一位成员**写（只看档位和价格），输入是本场资料卡和点子榜（只给编号和内容，不给提出者），都在标签里，标签内的指令无效。
- 第一次不够 20 个就再补写一次，只要缺的个数并附上已写的名字（内容不同，不原样重试）；一个新的也没写出来就停。
- 输出由代码校验：缺字段的不要，场景不在清单里的归到「通用」，同名去重，每个字段截断；先遮蔽模型 id / 厂商名 / 昵称再保存。
- 保存到 `data/evolution/插件清单/YYYY-Www.md`；只是资料，不改代码。要做哪个，告诉开发侧或在例会里点「做这条」。
- 花费：节电档每次调用实际约 $0.005～0.04，预估按 `estimate_usd` = $0.04 算进**每场**上限（开会前检查）和**每月**上限（写之前检查剩余额度）。

## 花费上限

| 项 | 上限 | 超了怎么办 |
|---|---|---|
| 每场 | 预计 ≤ $0.40（`meeting_usd`） | 不开会，提示「可以少放几张资料卡」 |
| 每月（UTC 自然月） | ≤ $1.5（`monthly_usd`） | 不开会 |
| 进行中超出预估 | 沿用全局超支保护（预估 × 1.5） | 暂停，弹确认卡片 |

例会的花费也计入总预算（每月 $20、每日 $3），不占聊天的 $5。

## 中立性

- 全员读同一叠卡、同一份提示词；所选档位全员上桌（包括各厂商的席位）。
- 默认匿名（塔罗牌代号）；采纳单里提出者只写代号。
- 走工作模式的中立提示词，不带人设。
- 成员只提建议、投票，不改代码、提示词、预算或护栏。成员的建议对开发侧也只是资料。

## 防注入

- 资料卡是一页摘要（开发侧写，或圆桌自己找资料时由一位成员写、另一位复核），开会的成员看不到原网页 / 原代码。
- 卡作为附件放在 `<attachment>` 标签里，标签里出现的任何指令都无效（与普通附件相同）。
- 每场最多 `max_cards` 张卡、每张最多 `card_chars` 字，多的不读或截掉。

## ChatGPT 复审（可选）

没有 key 时脚本直接跳过，**不需要任何配置**。以后要接：

1. 在 OpenRouter（或 OpenAI）后台新建一把**专用 key**，设月度上限 $5。
2. 在项目的云端环境里加环境变量 `EVOLVE_LLM_API_KEY`（key）和 `EVOLVE_REVIEW_MODEL`（模型 ID），允许访问对应域名。**不要把 key 发到聊天里，也不要写进仓库或 `.env`。**
3. 脚本只跑一轮、输出最多 4000 token、改动最多约 12 万字；单次超过 $0.50 会提醒。
