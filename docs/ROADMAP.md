# 路线图（每日自动推进）

> 每天由定时任务开一个新的 Code 会话，按本文件推进**一步**。用户已批准本文件列出的步骤 R1～R8；R9 起需要用户先确认，自动任务不得开工。
> 用户的总体要求与版本规划：v2.2 稳定版 → v2.3 桌面小人（网页版）→ v2.4 协同进化 → v3.0 三入口 + 日常 → v3.1 记忆 → v3.2 群聊 → v3.3 更多成员 → v3.4 本地化 → v4.0 完整生命。

## 分支规则
- 当前分支关系和合并建议见 `docs/STATUS.md`（`track/agent-claude-behavior` 已包含 `roadmap/auto`，线性领先，无需再合并分叉）。
- 所有自动步骤都在分支 `roadmap/auto` 上，一步叠一步，**不合并**到 `ccr-86975127-sv4cvy` 或 `main`（由用户决定）。
- 每次开工先 `git fetch origin ccr-86975127-sv4cvy roadmap/auto`，检出 `roadmap/auto`，再 `git merge origin/ccr-86975127-sv4cvy`（把用户在开发分支上的新改动带进来）。合并有冲突且无法明确解决时：停止，不提交，在汇报里说明。
- 绝不推送到 `ccr-86975127-sv4cvy` 或 `main`；绝不提交 `data/` 下的任何文件、`.env` 或任何 key。

## 每次运行的做法
1. 读 CLAUDE.md（自动加载）和本文件；**不要读 docs/PLAN.md**，除非本步说明要求。按 CLAUDE.md「必读索引」只读相关的 ARCHITECTURE 章节。
2. 找第一个状态为「未开始」或「进行中」的步骤（跳过标「需用户」的）。只做这一步。
3. 有详细说明文件的按文件做；没有的，先在 `docs/tracks/<线名>.md` 写一小段设计（做什么、改哪些文件、测试），再实现。范围控制在本步描述以内。
4. 开发时只跑相关测试；每完成一小段就提交并推送（防止额度中断丢失进度）。本步结束前跑 `ruff check . && ruff format --check . && pytest -q`，必须全部通过（环境里有 /opt/pw-browsers/chromium 时先 `export ROUNDTABLE_CHROMIUM=/opt/pw-browsers/chromium`）。
5. 完成后把本文件里该步状态改为「已完成（日期，提交号）」，未完成改为「进行中」并写下接着做什么；更新 `docs/tracks/<线名>.md`；提交、推送。
6. 需要用户拍板的事：写进该步的「待决」并按最保守的做法处理或跳过，不要替用户决定。
7. 最后用**通俗中文**汇报（会作为通知发给用户）：完成了哪一步、测试结果、用户需要在电脑上试什么（具体到点哪里）、下一步是什么、有没有需要用户决定的事。
