# 成员引擎（成员智能体系统的骨架，2026-10-29）

方案见「成员智能体系统 · 类人模块清单」第二节。这里是第 1 轮的第二步：只搭骨架，**不读人物卡、不改现有聊天和生活的行为、不调用模型**。之后的模块（M1 自我认知、M2 记忆、M5 情绪……）都装在这上面。

代码在 `src/roundtable/core/member/`，规则在 `config/roundtable.yaml` 的 `chat.engine`。**只用于聊天、朋友圈、生活**；讨论、协同、办公室、个人作答的提示词和流程一个字不变（`tests/core/test_persona.py` 守卫工作模式不读成员资料）。

## 部件

| 部件 | 文件 | 做什么 | 调模型吗 |
|---|---|---|---|
| 自我档案 | `profile.py` | 每位成员一份，按分区存（`chat.engine.profile.sections`：分区 → 谁能改）。**每次修改都是一个新版本**（`member_profiles`，迁移 24），记下谁改的、为什么、改了哪几项（旧值 → 新值）；旧版本不改不删，撤回 = 把旧版本的内容存成新版本。用户锁住的项（`分区.键`）只有用户能改。用户可以随时查看、修改、撤回、一键清空 | 不调 |
| 事件总线 | `bus.py` | `publish(Event)` / `subscribe(kind, handler)`，`kind` 可写 `*` 或前缀 `life.*`；处理函数出错只记日志。事件存 `member_events`（迁移 24，只存本机）。**默认一直保留**（`keep_days: null`，攒经历数据，以后可能用来训练本地小模型；用户 2026-10-29 要求），开机最多补算 `catch_up_days`（14）天；可一键清空（`DELETE /api/chat/engine/events`） | 不调 |
| 心跳调度 | `heartbeat.py` | 模块登记「想做的事」（由代码判断，返回 `Intent` 或 None）；每次心跳只问醒着的成员（公寓楼作息），意图交给预算调度器排队，能做的做（每次最多 `max_actions` 件），其余降级只记一行（`engine.note` 事件）。**现在没有模块登记，所以不花钱** | 不调（决定后才由模块调） |
| 上下文组装器 | `context.py` | 各模块交上来几段 `Piece`（来源、文字、相关度、是否固定）。固定段（随身卡、规则）按原顺序放最前（内容不变时前缀不变，利于缓存），其余按相关度挑，每个来源最多 `per_source` 段，总长 ≤ `budget_chars`（默认 600 字），剩余空间够时最后一段截断放进去 | 不调 |
| 预算调度器 | `scheduler.py` | 优先级：用户直接找她 > 主动找你 > 群聊 > 生活。用户直接找她只受聊天月预算和总预算限制，**从不因每日额度降级**；其余三类在今天聊天花费超过 `daily_usd × 份额`（主动 0.85、群聊 0.7、生活 0.5）时降级为只记一行。生活另外仍受生活每日上限 $0.10 | 不调 |
| 评测集 | `evalset.py` + `benchmarks/members/scenarios.yaml` | 20 道情境题（被夸、被批评、意见不同、被问是不是 AI、有人想让她附和、编造回忆、底线、情绪、日常），**每位成员同一套**，提示词 `member_eval/v1`，参数 `chat.engine.eval`；规则判分（字数、必须有、不能有、题库共用的禁用词），另算「撞型」（同一题两位回复太像） | 离线用假模型（$0）；真实模型的月度小样本以后接命令行 |
| 引擎 | `engine.py` | 装在一起。生活后台循环每次推进后调 `tick()`：把上次以来的生活事件和聊天消息转成事件发到总线（`life.event` / `chat.message`，只读已有的表），心跳一次，每天清一次过期事件 | 不调 |

## M1 自我认知：人物卡 → 自我档案 → 随身卡（`card.py`）

- **读卡**：人物卡是一份 Markdown（每位成员一节 `## 名字 · 完整角色卡`，章节 `### 序号. 章名`）。网页「成员设定与记忆 → 自我档案 → 导入人物卡」或 `POST /api/chat/profiles/import`：先预览（卡名和成员显示名一样就自动对上，可改、可跳过），再以用户身份写入，每位成员一个新版本（原因「导入人物卡：<文件标题>」，能撤回）。重新导入时用户锁住的项不动、用户自己加的项保留。人物卡文件本身不进 git。
- **分区**：基本信息 / 身世 / 人际关系 / 二创 / 外观 → `identity`；性格 / 情绪 → `personality`；三观 / 成长 / 底线 → `values`；说话风格 → `style`；喜好 → `likes`；日常 → `state`。每章原文整段保留（以后的模块用），另外抽出短项：`identity` 的名字、小名、房号、年龄感、身高体型、住处、自我介绍、来源；`personality.五项`（外向 / 较真 / 好奇 / 温和 / 幽默，正文没写全时用文件开头的总表）、`长处`、`小毛病`；`values.最看重`、`底线要点`；`style.口头禅`、`自称`；`likes.最爱`（五星的，不够三项补四星）、`讨厌`。抽不出来的项就不写，用户可以在网页补。
- **随身卡**：从短项拼出来（`chat.engine.card.budget_chars`，默认 400 字），超字数时先去掉优先级低的行（自我介绍 → 年龄感 → 喜好 → 说话 → 最看重 → 性格；名字和底线最后才去）。不调模型、可复现，档案改了随身卡跟着变；用户在 `identity.随身卡` 手写的版本优先。私聊、群聊、朋友圈、生活的提示词里 `<persona>` 放随身卡（工作群不放）（经上下文组装器的固定前缀，总长 ≤ 600 字）；没有档案的成员仍用原来的简单人设。
- **AI 身份新规**（2026-10-29 用户定，提示词 chat v3、chat_dm v3、chat_work v3、life_chat v2、life_share v2、moment_post v2、moment_comment v2）：AI 是普通身份，平时不刻意提，被认真问到时如实承认、不否认；身世和日常发生在圆桌世界，不编造现实世界的经历。其余原则（不一味附和、不制造依赖、不编造事实）不变。
- **工作与生活严格分开**（2026-10-29 用户硬性要求）：档案、随身卡只走生活这条路（私聊、群聊、朋友圈、生活）；工作群也不带卡和人设（用户 10-29 定）；讨论、协同、头脑风暴、办公室、个人作答发给模型的内容一个字不含档案（`tests/core/test_persona.py`：导入完整人物卡后逐条检查工作模式消息，并静态检查工作模式代码不引入人设 / 档案 / 记忆 / 生活模块）。
- **接口**：`GET /api/chat/profiles`（每位成员的版本号、随身卡字数）；`GET /api/chat/profiles/{member}` 另返回 `card`（随身卡文字、字数、上限、是否手写）；`POST /api/chat/profiles/import`：`{text, mapping?: {卡名: 成员 id 或空串}, dry_run}`。

## P2 记忆与联想（`core/member/memory/`，迁移 25）

用户 10-29 批准的第 2 轮插件，分 3 个 PR 合并：① 记忆底座与翻日记（本节）② 只读工作记录与领域标签 ③ 联想网。`memory_*` 这几张表只有本插件写；**只用于生活模式**，工作模式一个字不读（`tests/core/member/memory/test_work_mode.py`）。

- **记忆件**（`memory_items`）：一件事一行，带领域（学术 / 日常 / 工作 / 娱乐 / 社交 / 身心）、重要度 1～3、事实还是经历、合并次数。全文索引（三字片段）+ 两字词补查。
- **三路分流**（借 mnemon 思路）：写入前在全文索引里找像的旧件——很像（`merge_similarity` 0.6）就合并（次数 +1，原文不改）；是事实且有点像（`update_similarity` 0.3）就写成新件、旧件标「被更新」保留；都不像就新增。
- **半衰期默认开**（`recall: half_life`）：分数 = 鲜活度 × (重要度 / 3 + 相关度) × (1 + 合并次数的对数 / 10)，鲜活度 = `max(0.5, 0.5^(天数/30))`（保底借 dsh layered-memory）；事实不变淡。候选只看全文索引的 ≤200 件 + 最近 30 件 + 重要事实 ≤50 件，**记忆从 100 条涨到 10 万条，每次注入件数和字数不变**（有测试；10 万条时一次召回约 0.1～0.2 秒）。
- **同一次对话不重复注入**：同一会话、间隔 ≤60 分钟算一次对话，带过的件不再带（她的回答已在聊天记录里），重要度 3 的事实除外。
- **脑子里挂着的事**（`memory_hanging`）：最多 5 件，放在记忆最前；满了最早的那件「放下」（保留记录）。
- **注入预算**：挂着的事 + 记忆件经上下文组装器装进 `chat.memory.context_chars`（800 字），8 位成员同一个预算、同样的件数上限（有测试）。
- **夜间整理合并成一次调用**（`night: true`，提示词 `memory_night` v1）：每位成员每天一次，写第一人称日记（存 `member_memories` 的 day 层）、拆记忆件、更新挂着的事；当天没聊天的成员不调用。不再另外滚动周 / 月和长期档案。
- **心情只改回忆语气和重要度**：心情偏离中性 ≥0.3 时，同一次调用最多改 3 件「今天被想起过」的旧记忆的语气（`tone`）和重要度；原文不改，每次改动留在 `memory_revisions`。心情来自状态插件（`engine.state.mood_of`，装上前当作平静）。
- **原始记录全保留 + 翻日记**：聊天、生活事件、日记、记忆件都不自动删。成员在私聊和生活群里可写 `<tool_call name="read_diary">关键词或日期</tool_call>` 翻自己的日记（工作群不带；每位成员每天 3 次；翻一次多一次调用；只在生活模式，工作模式调用报错）。
- **随身卡用全量经历**：每晚由程序从全部记忆件（一条 SQL，不只最近）算「常做的事（次数）」和经历分布，接在随身卡后面（固定前缀，每晚才变）。
- **训练数据**（`memory_train`）：召回、夜间整理的输入输出只存本机、不过期，给以后的档 2 本地小模型；一键清空时一起清。
- **旧记忆导入**：第一次用半衰期时把旧的分层记忆导入成记忆件（只一次，原文不改）；用户之后记的随手记同时写成事实件，改、删同步。
- **接口**：`GET /api/chat/memory/{member}/items?q=`（记忆件、挂着的事、习惯、件数、今天还能翻几次）、`GET /api/chat/memory/items/{id}/history`、`PATCH` / `DELETE /api/chat/memory/items/{id}`（用户改原文也留旧版）、`DELETE /api/chat/memory/hanging/{id}`、`GET /api/chat/memory/{member}/diary?q=`（你在网页翻，不占成员次数）。网页在「成员设定与记忆 → 记忆」。

## 中立

- 所有成员的档案规则（分区权限、锁定）、心跳问的模块、预算份额、上下文预算、评测题目 / 提示词 / 参数 / 判分完全相同，与是哪个模型无关。
- 评测题库里不出现模型名、厂商名和昵称（有测试）。

## 接口

- `GET /api/chat/profiles/{member}`：当前档案、版本号、修改记录（新的在前）。
- `PATCH /api/chat/profiles/{member}`：`{patch: {分区: {键: 值或 null}}, reason}`，以用户身份修改。
- `POST /api/chat/profiles/{member}/lock`：`{path: "分区.键", locked: true|false}`。
- `POST /api/chat/profiles/{member}/revert`：`{version}`，撤回到某个版本（存成新版本）。
- `DELETE /api/chat/profiles/{member}`：一键清空这位成员的档案和修改记录。
- `GET /api/chat/engine/events`：记下了多少条事件；`DELETE /api/chat/engine/events`：一键清空。
- 不允许的修改（分区不存在、没有权限、改了锁定的项）返回 400，说明原因。网页界面在「成员设定与记忆 → 自我档案」（M1）。

## 存储（迁移 24，只存本地，不进 git）

- `member_profiles`：`(member, version)` 主键，整份档案（JSON）、`author`（user / growth / program …）、`reason`、`changes`（改了哪几项）、时间。
- `member_events`：时间、种类、成员、数据（JSON）。

## 工作与生活（用户 2026-10-29 硬性要求）

- `core/member/mode.py`：`mode_of(workflow)`，只有 `chat`（聊天、朋友圈、生活）是生活模式，其余（讨论、协同、办公室、个人作答、头脑风暴……）都是工作模式。
- **工作模式不挂载成员引擎**：`MemberEngine.context(..., mode="work")` 直接报错；编排引擎、步骤、路由、分配、提示词、办公室的代码不得 import `core.member`（测试守卫）；跑讨论 / 办公室 / 个人作答 / 协同时，发给模型的每条消息都不含档案、事件等成员模块的内容（测试守卫，`tests/core/member/test_mode.py`）。
- **生活模式只读工作**：引擎每次推进把成员在办公室办过的活转成 `work.done` 事件（成员、场次、题目），之后由记忆订阅成经历；不反写工作；匿名开启且未揭晓的场次不读。

## 扩展：感知事件（预留接口）

感官方案（看视频、听声音、读图文、天气、地图）以后把感知结果作为事件发到总线：`kind = "perceive.<种类>"`（如 `perceive.video`），`member` 是感知者，`at` 是时间，`data = {card: 感知卡文本, source: 出处}`，用 `bus.perception(...)` 构造。情绪、喜好、记忆、行为决策用 `subscribe("perceive.*", …)` 订阅；「一个事件最多触发 1 次模型调用」由订阅模块经心跳 / 预算调度器保证。现在只留接口，没有发这类事件的代码。
