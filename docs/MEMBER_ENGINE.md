# 成员引擎（成员智能体系统的骨架，2026-10-29）

方案见「成员智能体系统 · 类人模块清单」第二节。这里是第 1 轮的第二步：只搭骨架，**不读人物卡、不改现有聊天和生活的行为、不调用模型**。之后的模块（M1 自我认知、M2 记忆、M5 情绪……）都装在这上面。

代码在 `src/roundtable/core/member/`，规则在 `config/roundtable.yaml` 的 `chat.engine`。**只用于聊天、朋友圈、生活**；讨论、协同、办公室、个人作答的提示词和流程一个字不变（`tests/core/test_persona.py` 守卫工作模式不读成员资料）。

## 部件

| 部件 | 文件 | 做什么 | 调模型吗 |
|---|---|---|---|
| 自我档案 | `profile.py` | 每位成员一份，按分区存（`chat.engine.profile.sections`：分区 → 谁能改）。**每次修改都是一个新版本**（`member_profiles`，迁移 24），记下谁改的、为什么、改了哪几项（旧值 → 新值）；旧版本不改不删，撤回 = 把旧版本的内容存成新版本。用户锁住的项（`分区.键`）只有用户能改。用户可以随时查看、修改、撤回、一键清空 | 不调 |
| 事件总线 | `bus.py` | `publish(Event)` / `subscribe(kind, handler)`，`kind` 可写 `*` 或前缀 `life.*`；处理函数出错只记日志。事件存 `member_events`（迁移 24，只存本机）。**默认一直保留**（`keep_days: null`，攒经历数据，以后可能用来训练本地小模型；用户 2026-10-29 要求），开机最多补算 `catch_up_days`（14）天；可一键清空（`DELETE /api/chat/engine/events`） | 不调 |
| 心跳调度 | `heartbeat.py` | 模块登记「想做的事」（由代码判断，返回 `Intent` 或 None）；每次心跳只问醒着的成员（公寓楼作息），意图交给预算调度器排队，能做的做（每次最多 `max_actions` 件），其余降级只记一行（`engine.note` 事件）。**现在没有模块登记，所以不花钱** | 不调（决定后才由模块调） |
| 上下文组装器 | `context.py` | 各模块交上来几段 `Piece`（来源、文字、相关度、是否固定）。固定段（随身卡、规则）按原顺序放最前（内容不变时前缀不变，利于缓存），其余按相关度挑，每个来源最多 `per_source` 段，总长 ≤ `budget_chars`（默认 600 字），剩余空间够时最后一段截断放进去 | 不调 |
| 预算调度器 | `scheduler.py` | 优先级：用户直接找她 > 主动找你 > 群聊 > 生活。用户直接找她只受聊天月预算和总预算限制，**从不因每日额度降级**；其余三类在今天聊天花费超过 `daily_usd × 份额`（主动 0.85、群聊 0.7、生活 0.5）时降级为只记一行。生活另外仍受生活每日上限 $0.10 | 不调 |
| 评测集 | `evalset.py` + `benchmarks/members/scenarios.yaml` | 20 道情境题（被夸、被批评、意见不同、被问是不是 AI、有人想让她附和、编造回忆、底线、情绪、日常），**每位成员同一套**，提示词 `member_eval/v1`，参数 `chat.engine.eval`；规则判分（字数、必须有、不能有、题库共用的禁用词），另算「撞型」（同一题两位回复太像） | 离线用假模型（$0）；真实模型的月度小样本以后接命令行 |

## M1 自我认知：人物卡 → 自我档案 → 随身卡（`card.py`）

- **读卡**：人物卡是一份 Markdown（每位成员一节 `## 名字 · 完整角色卡`，章节 `### 序号. 章名`）。网页「成员设定与记忆 → 自我档案 → 导入人物卡」或 `POST /api/chat/profiles/import`：先预览（卡名和成员显示名一样就自动对上，可改、可跳过），再以用户身份写入，每位成员一个新版本（原因「导入人物卡：<文件标题>」，能撤回）。重新导入时用户锁住的项不动、用户自己加的项保留。人物卡文件本身不进 git。
- **分区**：基本信息 / 身世 / 人际关系 / 二创 / 外观 → `identity`；性格 / 情绪 → `personality`；三观 / 成长 / 底线 → `values`；说话风格 → `style`；喜好 → `likes`；日常 → `state`。每章原文整段保留（以后的模块用），另外抽出短项：`identity` 的名字、小名、房号、年龄感、身高体型、住处、自我介绍、来源；`personality.五项`（外向 / 较真 / 好奇 / 温和 / 幽默，正文没写全时用文件开头的总表）、`长处`、`小毛病`；`values.最看重`、`底线要点`；`style.口头禅`、`自称`；`likes.最爱`（五星的，不够三项补四星）、`讨厌`。抽不出来的项就不写，用户可以在网页补。
- **随身卡**：从短项拼出来（`chat.engine.card.budget_chars`，默认 400 字），超字数时先去掉优先级低的行（自我介绍 → 年龄感 → 喜好 → 说话 → 最看重 → 性格；名字和底线最后才去）。不调模型、可复现，档案改了随身卡跟着变；用户在 `identity.随身卡` 手写的版本优先。私聊、群聊、朋友圈、生活的提示词里 `<persona>` 放随身卡（工作群不放）（经上下文组装器的固定前缀，总长 ≤ 600 字）；没有档案的成员仍用原来的简单人设。
- **AI 身份新规**（2026-10-29 用户定，提示词 chat v3、chat_dm v3、chat_work v3、life_chat v2、life_share v2、moment_post v2、moment_comment v2）：AI 是普通身份，平时不刻意提，被认真问到时如实承认、不否认；身世和日常发生在圆桌世界，不编造现实世界的经历。其余原则（不一味附和、不制造依赖、不编造事实）不变。
- **工作与生活严格分开**（2026-10-29 用户硬性要求）：档案、随身卡只走生活这条路（私聊、群聊、朋友圈、生活）；工作群也不带卡和人设（用户 10-29 定）；讨论、协同、头脑风暴、办公室、个人作答发给模型的内容一个字不含档案（`tests/core/test_persona.py`：导入完整人物卡后逐条检查工作模式消息，并静态检查工作模式代码不引入人设 / 档案 / 记忆 / 生活模块）。
- **接口**：`GET /api/chat/profiles`（每位成员的版本号、随身卡字数）；`GET /api/chat/profiles/{member}` 另返回 `card`（随身卡文字、字数、上限、是否手写）；`POST /api/chat/profiles/import`：`{text, mapping?: {卡名: 成员 id 或空串}, dry_run}`。

## P2 记忆与联想（`core/member/memory/`，迁移 25）

用户 10-29 批准的第 2 轮插件，分 3 个 PR 合并：① 记忆底座与翻日记（本节）② 只读工作记录与领域标签 ③ 联想网。`memory_*` 这几张表只有本插件写；**只用于生活模式**，工作模式一个字不读（`tests/core/member/memory/test_work_mode.py`）。

- **记忆件**（`memory_items`）：一件事一行，带领域（学术 / 日常 / 工作 / 娱乐 / 社交 / 身心）、重要度 1～3、事实还是经历、合并次数。全文索引（三字片段）+ 两字词补查。
- **三路分流**（借 mnemon 思路）：写入前在全文索引里找像的旧件——很像（`merge_similarity` 0.6）就合并（次数 +1，原文不改）；是事实且有点像（`update_similarity` 0.3）就写成新件、旧件标「被更新」保留；都不像就新增。
- **半衰期默认开**（`recall: half_life`）：分数 = 鲜活度 × (重要度 / 3 + 相关度) × (1 + 合并次数的对数 / 10)，鲜活度 = `max(0.5, 0.5^(天数/30))`（保底借 dsh layered-memory）；事实不变淡。候选只看全文索引的 ≤200 件 + 最近 30 件 + 重要事实 ≤50 件，**记忆从 100 条涨到 10 万条，每次注入件数和字数不变**（有测试；10 万条时一次召回约 0.1～0.2 秒）。
- **同一次对话不重复注入**：同一会话、间隔 ≤60 分钟算一次对话，带过的件不再带（她的回答已在聊天记录里），重要度 3 的事实除外。
- **脑子里挂着的事**（`memory_hanging`）：最多 5 件，放在记忆最前；满了最早的那件「放下」（保留记录）。
- **注入预算**：挂着的事 + 记忆件经上下文组装器装进 `chat.memory.context_chars`（800 字），8 位成员同一个预算、同样的件数上限（有测试）。
- **夜间整理合并成一次调用**（`night: true`，提示词 `memory_night` v1）：每位成员每天一次，写第一人称日记（存 `member_memories` 的 day 层）、拆记忆件、更新挂着的事；当天没聊天的成员不调用。不再另外滚动周 / 月和长期档案。
- **心情只改回忆语气和重要度**：心情偏离中性 ≥0.3 时，同一次调用最多改 3 件「今天被想起过」的旧记忆的语气（`tone`）和重要度；原文不改，每次改动留在 `memory_revisions`。心情来自状态插件（`engine.state.mood_of`，装上前当作平静）。
- **原始记录全保留 + 翻日记**：聊天、生活事件、日记、记忆件都不自动删。成员在私聊和生活群里可写 `<tool_call name="read_diary">关键词或日期</tool_call>` 翻自己的日记（工作群不带；每位成员每天 3 次；翻一次多一次调用；只在生活模式，工作模式调用报错）。
- **领域标签**（②）：夜间整理时模型给每件标领域；没标或标了表外的，用关键词表兜底（`domains.py`，所有成员同一张表）。习惯摘要按领域算经历分布。
- **生活只读自己的工作记录**（②）：夜间整理时读这位成员自己在讨论、协同、个人作答、头脑风暴、办公室里参加过的场次（往回 `work_lookback_days` 14 天），每场记成一件「工作」领域的经历（同一场只记一次），也放进当晚的 `<work>` 材料。匿名开启且未揭晓的场次不读，揭晓后再补上；邮件、革新例会等后台任务不算；从不反写工作。
- **联想网**（③，M22 档 1 的记忆部分，`links.py`，程序算不调模型）：两件记忆同一晚整理出来或同一次被想起就连得更紧（赫布：`w ← w + 0.2 × (1 − w)`），每晚衰减 2%、低于 0.05 删掉、每件最多 20 条连接（记忆再多也不爆）。召回时从分数最高的 4 件顺着连接扩散 2 步，多带 1 件「【想起】…」。每晚从近几天的件出发按强度随机走 2 次、每次 3 步（随机数由成员和日期决定，可复现），走到的旧事放进当晚 `<drift>`，可能写进日记；走过的路轻轻加强（回放巩固）。连接和游走都记进训练数据。
- **随身卡用全量经历**：每晚由程序从全部记忆件（一条 SQL，不只最近）算「常做的事（次数）」和经历分布，接在随身卡后面（固定前缀，每晚才变）。
- **训练数据**（`memory_train`）：召回、夜间整理的输入输出只存本机、不过期，给以后的档 2 本地小模型；一键清空时一起清。
- **旧记忆导入**：第一次用半衰期时把旧的分层记忆导入成记忆件（只一次，原文不改；只导入长期档案、用户写的和 ★ 行，日记和周 / 月小结不逐行抄，免得和日记重复）；用户之后记的随手记同时写成事实件，改、删同步。
- **不存空内容**：只有标题没有正文的日记和记忆件（如「10月24日回忆录：」，多半是生成被截断）直接丢掉。旧版导入留下的重复件和空件在本机清理一次（`clean_old_items`：只删只出现过一次、没改过的；日记原文不动）。
- **接口**：`GET /api/chat/memory/{member}/items?q=`（记忆件、挂着的事、习惯、件数、今天还能翻几次）、`GET /api/chat/memory/items/{id}/history`、`PATCH` / `DELETE /api/chat/memory/items/{id}`（用户改原文也留旧版）、`DELETE /api/chat/memory/hanging/{id}`、`GET /api/chat/memory/{member}/diary?q=`（你在网页翻，不占成员次数）。网页在「成员设定与记忆 → 记忆」。

## P5 决定与表达·说话风格（`core/member/voice.py`）

用户 10-29 验收群聊反馈「回复还是没有活人感」，第 3 轮的 P5 提前做「表达」这一半（关系相关的决定等 P4）。**只用于生活群和私聊**：工作群、讨论、协同、办公室、个人作答一概不挂载（`tests/core/member/test_voice.py`、`test_mode.py`）。本插件只读档案，不写任何数据。规则在 `chat.engine.voice`。

- **说话习惯**：从档案 `style.说话风格`（人物卡第⑥章原文）由程序抽出句子长短（短 / 中 / 长 → 一条大约 25 / 45 / 80 字以内）、语气词、口头禅、常用表情、自称和几句示范；不调模型，档案改了跟着变。人物卡写法不统一（加粗列表、一段话、「第一，……」），抽取对这些写法都有测试。
- **说话模式档位**（借 dsh maid）：外向 ≤2 话少、≥4 话多、其余平常；档位决定「接话」那一行、最多拆几条、拆条间隔倍数（话少的停得久）。幽默分决定表情包频率那一句。用户可以在档案写 `style.说话模式 = quiet / normal / chatty` 直接指定。
- **进提示词**：chat v6 / chat_dm v6（在 v5 主时区的基础上） 的 `<voice>` 段，8 位同一个字数上限（`budget_chars` 260），示范句每次按消息编号轮换着带 2 句（只学语气不照抄）；没有档案的成员写「没写：用你自己的说话风格」。v6 同时要求接住对方话里具体的点、可以只回几个字、不先附和再重复、「每人发一个」时别和前面的人挑一样的。
- **节奏**：`VoicePolicy` 实现 `ActionPolicy`（新增 `voice()` 方法给提示词用），由 `RoundtableService` 赋给 `chats.policy`。
- **说出口前自查**（程序查，$0）：和自己最近 5 条太像、和别人这一轮说的太像（跟风）、开头附和且后面没几个字（光附和）、口头禅最近 3 条用过、记忆为空却说「上次我们……」（编造回忆）。群里没被点名、只是跟风或光附和的那条**直接不发**；其余命中才用她自己的聊天档模型改写一次（`voice_rewrite` v1，每月上限 $0.05），问题没变少就发原文。之后照常过说话底线（`plain_talk`）。
- **第二块：跨消息重复**（用户电脑数据核查出的「AI 味」大头）。自查扩到成员之间的生活互聊（`life`）、上网分享（`share`）、朋友圈动态（`moment`）和评论（`comment`）：
  - 新规则：开头前 3 个字和最近 2 条以上（自己的或别人的）一样算套句式（`opening`，如「刚刷到」）；她最近 72 小时在各处说过 2 次以上的四字话题（如「番茄牛腩」）再提算炒冷饭（`rechew`，对方这次问起的不算）；附和开头 + 后面跟别人说的差不多算附和接龙。
  - 生活互聊、朋友圈动态和成员之间的评论没人在等她：查出跟风、重复、套句式就**不发**（$0，互聊这一段收尾）；回你的评论和上网分享改写一次。朋友圈动态和自己最近 7 条比的门槛更严（0.4）。
  - 一个人待着、什么也没发生（`今天的事：没有特别的事`、没聊天）的日子不发朋友圈（`moments_need_event`）。
  - 提示词 life_chat v3、life_share v3 带 `<voice>`；分享不再要求「只看到了摘要」「未核实」的固定说法，改成必要时用自己的话带一句。
- **评测**：题库加 `group` 类 3 题（各发一个表情包、周末干嘛、照头像描述表情包），标 `distinct: true`，两位撞型都算不合格（「8 人回复不雷同」）。

## P8 关于你（`core/member/about.py`）

用户 10-29 批准的第 3 轮插件，分两块合并：① 画像（本节）② 用户状态数据和开关（正在放的歌、电脑空闲、在玩游戏、课表 DDL、邮件栏，默认全关）。**一份画像 8 位共用**，只放事实、来源、证据和把握度；每位成员对你的**看法**不在这里（归 P4 关系）。**只用于私聊和生活群**：工作群、讨论、协同、办公室、个人作答一概不挂载（`AboutYou.lines(..., mode="work")` 报错；`tests/core/member/test_about.py` 守卫发给工作模式的每条消息都不含画像）。规则在 `chat.engine.about`。

- **线索从哪来**：夜间整理那一次调用顺带交最多 `clues_per_night`（3）条线索（提示词 `memory_night` v2 的 `about`，不多调用）。每条必须引用户原话里连续的一段（≥4 字）；程序在那一天用户在私聊、生活群里发的消息里找这段原话，**对不上就不记**（防编造）；工作群里的话不读，撤回的消息不算。记忆插件只把线索交出去（`MemoryKeeper.on_clues`），画像只由本插件写。
- **来源与把握度**：你在画像页写的或改过的 = 1；你亲口说的（`said`）= 0.9，不变淡；成员推测的从 0.5 起步，每多一条不同的原话 +0.15（最多 0.85），30 天没有新证据就淡一半，低于 0.25 算「变淡了」，聊天不再带（画像页还看得到）。同一句原话被几位成员都注意到只算一条证据（记下谁也注意到了）。
- **不推测**：健康、宗教、政治、性取向、经济、行动轨迹（`blocked` 词表）。线索文字、原话片段或整条原话里出现就不记；你自己在画像页写的不拦。
- **你的操作**（网页「成员设定与记忆」最前面的「关于你」）：看证据（时间、会话、谁注意到的、你的原话，可「去看原话」跳回聊天）、改（改过的算你写的，旧的留在修改记录）、删、点「不对」（删掉并记进「不对」名单，之后像它的线索不再记；可取消）、锁定（不变淡，程序不再改它）、按领域关（不再记、聊天也不带，已有的留着给你看）、清空（可连「不对」名单一起清）、导出（Markdown / JSON）。

## P6 成长（`core/growth.py` + `core/member/growth/`）

用户 10-29 批准的第 3 轮插件，分两个 PR：① 每周反思底座 ② 习惯计数、技能熟练度、月度「这个月的我」报告。**只用于生活模式**；工作模式不挂载（`run(..., mode="work")` 报错；工作模式代码不 import，`tests/core/test_growth.py` 守卫）。**成长是唯一能以 growth 身份写自我档案 personality / values / style / likes 的插件**（测试守卫：别的代码不出现 `author="growth"`）。规则在 `chat.engine.growth`。

- **每周一次**：每周一（`weekday`）起，生活每次推进时顺带看一眼，上一周还没反思过的成员各反思一次；网页「成员设定与记忆 → 成长」也能点「现在反思」（每周只一次）。
- **材料 = 程序整理的一周**（`member/growth/week.py`，不调模型）：上一周的日记（按句拆开）、记下的事（含工作领域的经历）、用户对她说过的最近几句（工作群不算），每行带编号；用户说的话和提到用户的经历标「受用户影响」。总长 ≤ `material_chars`（4000 字），8 位相同。另带档案里成长能改的短项、锁定清单、全量经历的习惯摘要（P2 的 digest）。
- **经历太少就跳过**：有经历的天数 < `min_days`（3）或条数 < `min_lines`（5）不调用模型，时间线记一条「上周只有 N 天、M 条经历，太少了」。
- **提议**（`growth_reflect` v1，成员自己的聊天档模型）：最多 `max_changes`（3）条，每条必须写 `evidence`（经历编号）和 `quote`（照抄的原话）。只有三种改法：`score` 五项性格分一项 ±1；`add` / `remove` 在 `lists` 列出的列表里加 / 去一项（长处、小毛病、最看重、口头禅、最爱、讨厌）。人物卡整段原文不让成长改。
- **程序把关**（`member/growth/gate.py`，按顺序叠在同一份档案副本上检查）：只能这样改（结果仍在 1～5、新项 ≤20 字、列表 ≤8 项）→ 用户锁定项不动、分区权限 → 引用的编号存在、原话的两字片段 ≥60% 出现在所引经历里 → 五项性格分每月（本地日历月）最多改 `core_monthly_steps`（1）格 → 8 人不撞型（改完和任何一位别人的五项分差 < `min_distance` 2 且比原来更近就拦；口头禅不和别人重样）→ 受用户影响的改动在最近 8 周里不超过 `user_share`（三成；不到 10 条时按 10 条算）。
- **重试最多一次**（借 dsh answer-reviewer）：提议不是 JSON、或提了但一条也没过把关时，带着被拦下的原因再请求一次（第二次的请求和第一次不同，不原样重试）；没想改（`changes` 为空）不重试。
- **评审，不自评**（`growth_review` v1）：从别的成员里按（周、成员）固定的随机数均匀抽一位，用她的模型给通过把关的每条打 1～5 分，低于 `review.min_score`（3）的不改；评审没回应（额度不够、调用失败）时这周都不改，下次推进再试。
- **写档案**：通过的每条各存成档案的一个新版本（author = growth，原因「成长 2026-W43：……」），写之前按此刻的档案重算一遍（前一条被评审拦下时，后一条不会把它带进去）。
- **成长时间线**（`member/growth/timeline.py`，存在 `app_settings` 的 `member_growth:<成员>`，不加迁移，只有本插件写）：每条记改了什么（旧 → 新）、为什么、引用的经历和原话、评审几分、是否受用户影响；被拦下的记原因（撞型时记和谁）；跳过的记原因。每人最多留 500 条。
- **撤回**：时间线里的每条改动都能单独撤回——按此刻的档案算反向的一步（性格分减回去、加的去掉、去掉的加回来），以用户身份存成档案的新版本；撤回的不再计入每月格数和用户影响占比。
- **每周本地备份**：全部成员反思完，把每位成员的档案和成长数据写成数据库旁边的 `growth_backups/<周>.json`，只留最近 `backups`（8）份。只存本机，不进 git。
- **花费**：每次调用的预估一样（`estimate_usd`，8 位相同），步骤记 `growth`，计入生活每天的上限（$0.10）、聊天月预算和总预算；每周每位成员最多 3 次调用（提议、可能的一次重试、评审），约 $0.002～0.006。额度不够时这周先不反思，下次推进再试。
- **习惯计数（M17，②）**（`member/growth/habits.py`，程序算不调模型）：读事件总线存下的**全部**事件（`member_events` 一直保留），按成员累加——生活里做什么（聚在一起 / 两人聊天 / 一个人待着）、常去哪、在哪个时段说话（早上 / 中午 / 下午 / 晚上 / 深夜）、在办公室干活、看过听过什么。每项记总次数、跨了几周、最后一次是哪周。第一次从头算，之后每次推进只读游标以后的新事件；清空成长数据后会从头再算。次数 ≥ `habits.min_count`（5）且跨 ≥ `habits.min_weeks`（3）周才算习惯（偶尔一次不算）。
- **技能熟练度（M18，②）**：按记忆件的领域（学术 / 日常 / 工作 / 娱乐 / 社交 / 身心）把全部经历的件数加合并次数当经验，等级 = ⌊log2(1 + 经验)⌋（最多 10 级：入门 / 熟悉 / 熟练 / 拿手 / 精通），越往上越难升。
- 习惯和熟练度接在 P2 的「常做的事」后面进每周反思的 `<habits>` 材料（≤160 字）——习惯、熟练度由全量经历累积，具体回忆仍只少量注入。
- **月度「这个月的我」（②）**（`member/growth/report.py`，程序算不花钱）：每月 1 号起，生活推进时给上个月有经历的成员各写一份——有经历的天数、记下的事、反思了几周、改了几处（撤回、被拦下几处）、受你影响的占比、五项性格分从多少到多少、设定加了 / 去了什么、习惯前几项、熟练度升了几级（和上一份报告比）。最后一句固定写明：这些数字说明成员「表现得像」在变化，**不等于 TA 有主观体验**。每人最多留 `report.keep`（24）份。
- **接口**：`GET /api/chat/growth/{member}`（时间线、上次反思的周、该反思的周、规则、习惯、熟练度、月度报告）；`POST /api/chat/growth/{member}/run`（马上反思上一周，已反思过返回 409）；`POST /api/chat/growth/{member}/revert` `{id}`（撤回一条）；`DELETE /api/chat/growth/{member}`（清空时间线，档案本身不动）。网页在「成员设定与记忆 → 成长」。

## P4 关系（`core/member/relation.py`）

第 4 轮插件，分两个 PR：① 和你的阶段、同事之间的亲近度与看法（本节）② 每位成员对你的见解（按她自己的性格和三观理解 P8 画像，标「我觉得」，每周更新）。**只用于生活模式**；工作模式不挂载（`line(..., mode="work")` 报错；分配、路由、办公室、编排、步骤的代码不读关系，`tests/core/member/test_relation.py` 守卫），**只影响生活里谁和谁聊，不影响工作派活**。规则在 `chat.engine.relation`，不调模型、不花钱，8 位规则和分值相同。

- **和你**：你说话后她在 `reply_window_minutes`（30）分钟内接了才算一来一回（你一句话她只算一次，拆成几条也只算一次）；私聊记 `dm`（1）分、群里记 `group`（0.5）分；工作群不算。每天最多记 `user_daily_cap`（6）分。
- **阶段**（`stages`）：新邻居 → 熟悉（一起聊过 3 天、15 次来回）→ 老朋友（20 天、150 次、从认识到现在跨 6 周）。**只升不降**，每次升阶记一条（时间、阶段）。一天刷几百句也只算一天，成不了老朋友（有测试）。
- **亲近度**（0～1）= 1 − e^(−分数 / 尺度)，和你用 `user_scale`（40）、同事之间用 `scale`（12）；分数不来往按半衰期 `half_life_days`（60 天）变淡（读的时候按经过的时间算，补算时乱序也一样）。`quiet_days`（14）天没来往，「和你」那一行带「有阵子没聊了」。
- **同事之间**：生活里碰到一起（`gather` 1 分，记在哪碰到）、两人私下聊天（`pair` 2 分）、生活群和私聊里一来一回（`chat` 0.3 分，自己接自己不算）、一起在办公室干过同一件活（`work` 0.5 分，只读 `work.done`，同一场只算一次，从不反写）。两人的分数对称，各存在自己的那份里；每对每天最多 `peer_daily_cap`（4）分。
- **看法**（程序写）：亲近度标签（走得近 / 挺熟 / 点头之交 / 不太熟）+ 次数最多的两种经历（「常在食堂碰到（4 次）」「一起干过 3 次活」），很久没来往加「最近没怎么来往」。
- **用处**：① 生活引擎挑谁和谁聊——傍晚两人私聊先随机挑一位，另一位按 1 + `pair_bias`（2）× 亲近度加权抽；聚在一起超过 3 人时同样按亲近度挑；谁和谁都没来往过时照旧均匀随机（可复现，生人也照样碰到）。② 私聊、群聊、朋友圈、生活的 `<persona>` 里接一行「和你：熟悉，认识第 12 天」（≤ `context_chars` 60 字，算在 600 字里）。③ 生活场景里加一行「交情：A 和 B 走得近」（≤ `scene_chars`）。
- **只有本插件写关系**：存在 `app_settings` 的 `member_relation:<成员>` 和 `relation.tracker`（认「一来一回」的房间游标、最近 200 场工作），不加迁移（测试守卫别的代码不写）。
- **接口**：`GET /api/chat/relation/{member}`（和你的阶段、亲近度、离下一阶段还差什么、升阶记录；和每位同事的亲近度、看法、次数）；`DELETE /api/chat/relation[?member=]`（清空，从头再按经历累积）。网页在「成员设定与记忆 → 关系」（成长下面）。

## P3 状态：心情、精力、本能反射（`state.py`、`instinct.py`）

- **全由程序算，模型不写情绪**：心情（-1～1）和精力（0～1）只按总线上的事件（`chat.message`、`life.event`、`work.done`、`perceive.*`）和规则表改。
- **快慢两层、会回到基线**：每次冲击一部分落到快层（心情半衰期 2 小时、精力 1 小时），一部分落到慢层（心情 48 小时、精力 10 小时）。心情 = 基线 + 慢层 + 快层；精力 = 作息曲线 + 慢层（疲劳）+ 快层。衰减是闭式的，读的时候按经过的时间算，不用定时跑；补算时事件乱序也算得一样。参数在 `chat.engine.state`。
- **基线读自我档案**（只读）：心情基线来自五项性格的外向 / 幽默 / 温和和人物卡第 5 章「情绪」里的少量关键词；情绪敏感度（心情冲击乘它）来自较真 / 温和和关键词；作息（几点起、几点睡、是否夜猫子）从第 8 章「日常」里的钟点读出（6:30、十一点、半夜……），读不到就用公寓楼作息。
- **本能反射**：事件 → 刺激（标签：被 @、私聊、被批评、被夸、自己说话、生活里的事、干完活……，外加「本该在睡觉」、此刻精力和心情）→ `Instinct.react` → 反射（改心情 / 精力、动作、一行说明）。现在是规则表 `chat.engine.state.reflexes`（被 @ 秒回、你来私聊、深夜被叫醒犯困、被批评、被夸害羞、说多了累……，8 位同一张表）；以后换成小网络（M22 档 1）只要实现同一个 `react`。每次反射发一个 `state.reflex` 事件（动作留给之后的「决定与表达」）。
- **马上生效**：你发消息后、成员回应前，引擎先 `observe()` 一次（只把新消息发到总线，不心跳、不花钱），被 @、被批评的反射当场算进状态。
- **进提示词**：私聊、群聊、朋友圈、生活的 `<persona>` 里，随身卡后面加一行状态（≤ `context_chars` 80 字，8 位相同，算在 600 字里；随身卡这段前缀不变，不影响缓存）。工作群、讨论、协同、办公室、个人作答都不带（`StatePlugin.line(..., mode="work")` 报错；测试守卫发给工作模式的每条消息都不含状态）。
- **只有状态插件写状态**：存在 `app_settings` 的 `member_state:<成员>` 键（不加迁移），测试守卫别的代码不写。别的模块只读：`engine.state.mood_of(member)`（-1～1，记忆模块用来调回忆的语气和重要度）、`energy_of(member)`、`line(member)`。
- **接口**：`GET /api/chat/engine/state`（每位成员此刻的心情、精力、状态那一行、基线、最近的反射）；`DELETE /api/chat/engine/state[?member=]`（清空，回到基线）。
- 不调模型、不花钱。
## 日历事件

日历底座（docs/CALENDAR.md）每天第一次推进时发 `calendar.day`（今天是什么日子、是不是休息日）和 `calendar.upcoming`（N 天后的节日、成员生日、纪念日；生日的 `member` 是寿星）。只给数据，怎么过节由之后的生活引擎 / 行为决策订阅决定。
