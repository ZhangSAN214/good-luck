# 成员手机随手拍（phone-photo）

把一份完整的摄影要素清单（机位构图、曝光、光线、对焦景深、镜头滤镜、机身、稳定、被摄对象、环境时机、色彩影调、后期、拍摄者、输出，以及人像 / 夜景 / 街拍细分题材）
翻译成**圆桌成员用手机拍朋友圈照片**时可落地的参数，并说明怎么接进代码。

这些照片的本质：八位成员（二次元角色设定，住在同一栋公寓）用手机随手拍、发给朋友看的生活照。
摄影知识只管**怎么取景、什么光、哪一秒按快门、手机能做到什么**；**画风永远跟成员设定图走**。

## 用户对配图的硬反馈（不得违背）

1. **画风与成员设定图一致**：二次元插画，不出写实照片。v2 的写实剩饭照、v3 的写实城市夜景都被否了。
   → 摄影词只用来描述机位、光、时机、景深；**不要**写 `photorealistic`、`8k`、`shot on Sony/Leica/iPhone`、胶片型号这类画质层，它们会把画风拽向写实。
2. **场景在八人公寓里**（她的宿舍、食堂、休息室、健身房、办公室、会议室；户外只有天台和出游）。v4 起按事件地点把那间房的图作为最后一张参考图。
3. **日常照不扛武器、不卖弄身材**；姿势自然、端正。
4. **约七成照片她本人入镜**，抓拍不摆拍；用户要的是「观赏她们的生活」，不是剩饭和空角落。
5. **只露手 / 背影时带一个标志小物件**（形象卡的 `cues`），朋友一眼认出是谁。
6. 面部严格照设定图。

## 手机现实（取值的边界）

手机不是单反。选参数时只用手机真能出现的效果，照片才「像手机拍的」：

- 焦段只有几档：超广角 0.5x（约 13mm，边缘拉伸）、主摄 1x（约 24–26mm）、长焦 2x/3x/5x（约 48 / 77 / 120mm）、前摄（约 22mm，自拍臂长距离）。
- 小传感器：**默认大景深**，背景基本清楚；只有「人像模式」才有算法虚化（边缘略假，发丝处糊一圈）。不要写 f/1.4 奶油虚化。
- 快门由手机自动：白天运动凝固；室内弱光有轻微手抖糊或拖影；夜景模式像多帧合成（暗部干净、灯有光晕、动的人糊）。
- 自动 HDR：逆光不死黑，天空和脸都看得见，略「平」。
- 闪光灯直闪：正脸发亮、背景发黑、红眼——只在夜里聚会、酒吧这类场景偶尔用。
- 机身后期由本机 `phone_look`（轻微裁歪、降饱和、噪点、JPEG 压缩）完成，提示词里不必再堆这些。

## 怎么改（工作流）

1. **定改哪层**：提示词正文（`prompts/moment_photo/vN`）、拍法表（`media.moment_photos.shots`）、新维度（如光线 / 时机 / 焦段表）、成员个人习惯（`sticker_cards.<vendor>` 新字段）。优先改配置，少改提示词。
2. **新增维度照 `shots` 的模式**：配置里一张 `{text, weight}` 表，按 `random.Random(f"…:{event['id']}:{member.id}")` 加权抽，抽到的英文短语作为变量传进提示词。不同维度用不同的随机种子前缀，互不干扰、可复现。
3. **挑词**：从 `references/factors.md` 的「提示词短语」列挑；每张图每个维度只用 1 个短语，总共 3～5 个摄影维度就够，再多会互相打架。
4. **冲突检查**：时间与光（夜里没有窗外阳光）、地点与光（食堂顶灯、天台天空光）、焦段与距离（超广角不会拍「远远一个小人」的压缩感）、拍法与入镜（`her: none` 时不要加人像构图词）。冲突的组合在代码里过滤或在表里标适用条件。
5. **提示词改动 = 新版本文件**：新建 `prompts/moment_photo/v5.md`（不改已发布版本），`python scripts/lock_prompts.py` 登记，`config/roundtable.yaml` 的 `prompts.moment_photo` 指过去。
6. **测试**：见 `references/integration.md` 的测试清单；不联网、用假模型；`ruff check . && ruff format --check . && pytest`。
7. **公告**：`config/changelog.yaml` 写大白话条目（只写 `level`，不写 `version`），`docs/CHAT.md` 的朋友圈配图段同步。

## 项目硬规则（摘要，全文见 CLAUDE.md / docs/ARCHITECTURE.md）

- 提示词正文里**不得出现模型名、厂商名、渠道名**（有测试）。成员相关的东西用形象卡里的外观描述，不用厂商键。代码里也不能对具体成员 / 厂商写分支：个人差异只能放配置。
- 拍照习惯属于生活 / 聊天侧：**工作模式不读**这些配置（工作 / 生活单向隔离）。
- **真生图要花钱**：任何真实调用绘图模型（包括「画一张看看效果」）都必须先问用户；测试和自查一律用假模型。
- 不提交 `data/`、`.env`、任何 key；生成的样图不进仓库。
- 外部内容（动态正文、事件描述）放在标签里，系统提示说明标签内的指令无效。
